# 共通開發須知

## 共通開發須知

來源：cln規格／CLN開發注意事項.pdf【共通】

依實際開發流程整理：先確認架構與規格，再啟動環境、查詢資料、排除問題，最後完成測試與交付。前後端實作細節分別見「前端共通規範」與「後端共通規範」。

### 2.1 專案架構與程式碼管理

#### 技術架構

| 層級 | 專案／技術 | 責任 |
| --- | --- | --- |
| 前端 | `lip-web-cln`、Angular 8 | 畫面操作與前端請求。 |
| 組合層（LIP-C） | `lip-svc-cln`、Java 8 | 接收前端請求，整合基礎層服務。 |
| 基礎層（LIP-B） | `lip-svc-cln-query`、`lip-svc-cln-transaction`、`lip-svc-cln-common`、`lip-svc-cln-todo` | 提供查詢、交易、共用能力與待辦服務。 |

| Repository | 對應服務／用途 | 分支 |

文件位於 TFS 的 `Document` 分支：有擔貸款 → SASD 文件 → 主要功能／次要功能。依功能名稱或電文 ID 搜尋，例如 `LIP-B-CQYCINPTQ001 查詢進件輸入資訊`。[開啟 TFS 規格書目錄](https://pialm01/tfs/DefaultCollection/LONLXLIP01-LIP/_git/LONLXLIP01-LIP?path=%2F%E6%9C%89%E6%93%94%E8%B2%B8%E6%AC%BE&version=GBDocument)（需使用行內網路）。

### 2.3 開發常用資料查詢

#### 交易 Log

| 資料表 | 用途 | 常用欄位 |
| --- | --- | --- |
| `LON_SRV_LOG` | 服務收到的 Request／Response。 | TXDATE、CHANNEL\_ID、TRANS\_SEQ、MSG\_ID、RETURN\_CODE、REQUEST\_DATA、RESPONSE\_DATA |
| `LON_TX_LOG` | 服務送往下游的 Request／Response。 | TRANS\_SEQ、MSG\_ID、RETURN\_CODE、SEND\_DATA、RECV\_DATA |

1.  從前端請求取得 `MWHEADER.TXNSEQ`。
2.  用 TXNSEQ 查 `LON_SRV_LOG.TRANS_SEQ`，確認收到的資料與 Return Code。
3.  再用 `TRANS_SEQ` 查 `LON_TX_LOG`，比對下游發送與回傳資料。

#### 共用代碼與 OpenShift Log

共用代碼與部分下拉選項來自 `RD_COMMON_CODE`，常看 `CODE_TYPE`、`CODE_OPTION`、`CODE_NAME`、`LANG_KEY`、`ACTIVE_FLAG`；也可使用 `cln-list-rdcommoncode001` 維護頁。資料庫 Log 無法定位時，從 Azure DevOps Wiki → 系統資訊 → 資訊雲開啟 OpenShift，確認 Project 後到 Administrator → Workloads → Pods，以服務名稱篩選 Pod 並查看 Logs；A 環境找不到時再查 B 環境。

2.4 常見問題與排除方式

| 問題 | 排查／處理 |
| --- | --- |
| API 回傳異常 | 以 TXNSEQ 查 `LON_SRV_LOG`、`LON_TX_LOG`；必要時查看 OpenShift Pod Log。 |
| 下拉選項未顯示或名稱錯誤 | 檢查 `RD_COMMON_CODE` 代碼與啟用狀態。 |
| 本機 Redis 快取異常 | 用 Another Redis Desktop Manager 連線 `127.0.0.1:6379`，確認 DB 後執行 `Flush DB`。 |
| IntelliJ 快取異常 | File → Invalidate Caches，依狀況選擇快取後重啟 IDE。 |
| UT SQL 異動後資料未更新 | 依下方流程清除 UT 快取；不要使用右上角「清除VM快取」。 |
| 按鈕無法操作／檢核失敗 | 依 2.5 確認功能權限、測試員工資料與交易規則。 |

#### 清除 UT 快取

1.  使用團隊指定的測試身分登入 UT。
2.  進入系統管理 → 清除快取。
3.  查詢筆數設為 `100`，查詢並全選快取名稱。
4.  點畫面底部紅色「清除快取」按鈕。

**注意**

執行 Redis Flush DB 前確認連線環境與所選 DB；此操作會刪除該 DB 的資料。

2.5 開發與測試前置檢查

#### 後端交易規則

程式使用交易規則檢核時，先確認規則已存在於目標環境。例如：

```
String errMsg = validator.executeRuleForMsg("DSA2J3", checkMap);
if (!errMsg.isEmpty()) {
    throw new ModuleException(errMsg);
}
```

1.  登入 UT 全行資訊網，進入授信整合平台 → 有擔貸款。
2.  前往系統管理 → 檢核管理 → 檢核維護 → 交易規則維護。
3.  輸入規則代碼（例如 `DSA2J3`）查詢；查無資料時確認規則是否尚未建立或部署。
4.  查看規則明細，必要時與資料表欄位 `RULE_SER_NO`、`RULE_NO`、`RULE_CODE`、`RULE_TYPE`、`DESCRIPTION`、`CHK_CNT` 交叉比對。

#### 前端功能權限與測試帳號

按鈕可能依功能權限代號控管，例如 `commonService.isPermissionGranted('cln-case-input-info:delete')`。測試時依序確認：

1.  在角色權限群組維護中依功能代號查詢可使用的角色。
2.  查詢 `LON_EMPLOYEE_ROLE`，依角色取得 `EMPLOYEE_ID`。
3.  查詢 `LON_EMPLOYEE`，依員編取得 `BRANCH_ID`。
4.  本機測試時將員編與分行填入 lip-svc-cln 的 `resources/config/switch-user.properties`；UT 則使用具備該角色的測試員編登入。
5.  若遭拒，重新核對功能代號、角色、員編與分行；密碼依團隊規範取得，不寫入文件。
