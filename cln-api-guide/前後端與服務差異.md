# 前後端與服務差異

## 先分清前後端與七種服務責任

CLN 分成兩層：使用者操作的 Angular 前端 lip-web-cln，以及七個後端模組。先看清前端的請求實際打到哪個後端，再依責任與入口型態判斷該改哪個後端模組，不要只依 endpoint 或功能名稱。

FRONTEND

### 前端層：一個畫面請求怎麼抵達後端

01 **Component** lip-web-cln 頁面

表單（FormGroup）與 PrimeNG 元件收集輸入，呼叫頁面 Service。

→

02 **Page Service** HttpClient

`POST /api/...`，用 query 參數帶 `msgid`（LIP-C-\*）。

→

03 **Interceptors** core/interceptors

包成 MWHEADER + TRANRQ、補 apiUrl、Token、語系與 loading。

→

04 **lip-svc-cln** 組合層 · LIP-C

經 nginx `/api/` 轉發進來；檢查上行後，依電文 ID 呼叫基礎層。

→

05 **基礎層服務** LIP-B

query／transaction／common／todo 查詢或寫入資料庫；RETURNCODE 由前端 ErrorInterceptor 統一判斷。

**前端只打組合層，組合層再呼叫基礎層**

依 `nginx.conf`，前端的 `/api/` 請求轉給 lip-svc-cln，例如 `POST /api/case/inputInfo/query`（LIP-C-CLNCINPTC001）；lip-svc-cln 再以電文 `LIP-B-CQYCINPTQ001` 呼叫 query 服務。所以前端不會直接呼叫 Query／Transaction 的 `/case/...` API，寫前端時對的是 LIP-C 電文。詳見「03 新人練習 → 先懂三層架構」。

BACKEND

### 後端層：七種服務責任

前五個是 Spring Boot REST service，多數沿用標準電文與 Controller → Service 入口：其中 lip-svc-cln 是前端呼叫的組合層，query、transaction、common、todo 是基礎層。批次走 Spring Batch Job，ZRWeb 則是傳統 Servlet WAR。

| 模組 | Repo 名稱 | 主要責任 | 入口型態／資料路徑 | 範例入口 | 注意事項 |
| --- | --- | --- | --- | --- | --- |
| QUERY | `lip-svc-cln-query` | 查詢、欄位映射與清單組裝；ServiceImpl 查詢 Repository／SQL，整理 DTO／VO 並產生標準 ResponseTemplate。 | Controller → Service → ServiceImpl → Repository／SQL → Response | `POST /case/inputInfo/query`  
LIP-B-CQYCINPTQ001 | 明確定義查無資料、空集合與 null 的行為 |
| TRANSACTION | `lip-svc-cln-transaction` | 新增／修改／刪除、業務檢核與狀態轉換；Service 編排 Check、外部整合與異動 VO，多表寫入由 DataProcessor 控制交易。 | Controller → Service → Check／VO → DataProcessor → Repository → Response | `POST /case/inputInfo/modify`  
LIP-B-CTNCINPTT001 | 外部服務副作用不會隨本地 DB rollback 一起撤銷 |
| COMMON | `lip-svc-cln-common` | 跨流程共用的地址正規化、客戶／科目查詢、承作權限、核定層級、合約影本計算與訊息發送 API。 | Controller（/common、/customer、/calculate）→ Service | `POST /common/address/query` | 與 `lip-lib-cln-common` 程式庫區分；外部服務錯誤轉換要追到 Service |
| TODO | `lip-svc-cln-todo` | 彙整 PS、徵審、產包、補件、覆核／委員會等角色的待辦清單與筆數；只提供清單，不執行待辦代表的異動。 | TodoController／ReviewController → Service → 清單回應 | `POST /todoPsList/query` | 分頁、排序、權限與空清單行為逐支核對；後續動作由其他 API 完成 |
| REST | `lip-svc-cln（C 層）` | 前端入口（LIP-C 電文），編排呼叫 query、transaction 等基礎層並組合回應；涵蓋案件、核決、覆核、信用、派件與規則引擎。 | Controller（/api/case、/api/approval…）→ Service → 依電文 ID 呼叫 LIP-B（部分功能直接查 DB）→ 組合 Response | `POST /api/case/inputInfo/query` | 新功能通常 LIP-C（此處）與 LIP-B（基礎層）各寫一支，功能碼相同 |
| BATCH | `lip-bch-cln（批次）` | 以 Spring Batch Job／Step／Tasklet 執行背景排程，例如評等更新、訊息發送／重送與 JCIC 處理；不是 REST API。 | Job → 前置檢查 → Step（Tasklet 或 Reader／Writer） | `CLNS0B007` 訊息通知 | JobParameters、chunk 邊界、重跑與重複處理要評估 |
| ZRWEB | `CLN_ZR_SRC`（`ZRWeb`） | 傳統 Servlet／JSP WAR，產生 jrxml 報表，並處理檔案上傳、下載、刪除與複製。 | web.xml → Servlet → Mod → ReqRespUtil 回應 | `RptGeneratorServlet` | WAR 部署、非 Spring Controller；multipart／Base64 格式個別確認 |

**共同底線**

以核定規格為契約；沿用 RequestTemplate／ResponseTemplate、共用例外與既有工具；不要自行推定欄位、錯誤碼、查無資料語意或業務規則。
