## 開發規範與 Code Review 要點

### 開發規範

來源：cln規格／CLN開發注意事項.pdf【前端】

寫前端頁面時一定要遵守的規則。lip-web-cln 分頁「拿到頁面怎麼寫」的步驟與骨架已套用這些規則；這裡是完整清單。

### UI 元件與樣式

-   UXD 套件網站（專案定版在 UXD 套件 v2.7.2）：
    
    元件　·　顏色與排版　·　Icon（需在行內網路）
    
-   畫面樣式參照 PLN 專案。
    
    [PLN 專案 Prototype（Adobe XD）](https://xd.adobe.com/view/662236a8-a3e9-48db-9569-f34e3db3e030-3371/screen/396707d4-8152-4dff-85fe-d34389113841)
    
-   數字輸入用 `lip-inputNumber`：會自動加千分位，用法與外觀跟 input 相同。專案內已有約 78 處使用，可搜尋參考。
    
    `[maxIntegerDigits]` 最多整數位數 · `[maxFractionDigits]` 最多小數位數 · `[minFractionDigits]` 最少小數位數（不加預設 0）· `[suffixText]` 後綴字元 · `[prefixText]` 前綴字元
    
-   必填標記 `uxd-label-title-required` 已統一寫在共用 SCSS（`src/styles/_form.scss`），直接用：`<span class="uxd-label-title-required"></span>`。
    
-   表格內純文字對齊：金額靠右、地址這類長文字靠左，其餘先置中；以規格書要求為準。
    
-   專案有掃 SonarQube，HTML 表格的 `th` 要加 `scope`，例如 `<th scope="col">股票代號</th>`。
    

### 頁面行為

-   新交易要在麵包屑後方補上規格名，分兩種情境：
    
    a. 有在 routing 設 path 的元件：到 `src/app/core/guards/function-id-auth-map.ts` 以完整畫面 path（例如 `/cln/case/caseinit`）為 key，加上 `['完整畫面 path', '元件名稱']`，麵包屑會自動在最後加上元件名稱。  
    b. 以彈窗顯示的元件：直接在 HTML 標題下方寫元件名稱（見「E. 彈窗」骨架）。
    
-   麵包屑與選單要新增資料的表：`LON_MENU`、`LON_MENU_TRANSLATION`、`LON_FUNCTION_AUTH`。
    
-   純文字顯示的欄位、表格中的欄位值，要加 `noblank` pipe，例如 `{{ tranrs.CustomerName | noblank }}`。
    
    值為 null 或空字串時會顯示成「-」。
    
-   畫面要拿使用者權限，一律用 `CommonService` 的 `userProfile$`。
    
    不要用 UserService，那是儲存代理人權限用的。
    
-   input／textarea 要加 disabled，寫 `[attr.disabled]="條件式 ? true : null"`。
    
    一定要寫 `null`，否則只要屬性存在就會被停用，條件為 false 也一樣。
    
-   執行成功都要給 toast；如果是儲存成功，要重查畫面。
    
-   送出會使用案件編號的查詢或異動前，依情境呼叫 `checkApplyIdChange`；包含由 `@Input` 傳入的案件編號。
    

### 程式風格

-   Component 的 ts 成員依下列順序排列：`@ViewChild → @Input → @Output → 全域變數 → constructor → 生命週期 → 其他方法`。
    

```
@ViewChild()
@Input()
@Output()
全域變數
constructor() { }
ngOnChanges() { }
ngOnInit() { }
ngOnDestroy() { }
其他方法
```

本專案使用 Angular 8，不支援在元件中使用 `inject()`；需要依賴注入時請沿用 constructor。

### 表單與程式品質

-   FormControl 預設值用 `null`，不用 `''`；唯讀欄位不加未使用的 Validators。
    
-   明確標註型別或使用 interface，不用 `any`；只賦值一次用 `const`，需要重新賦值才用 `let`。
    
-   移除未使用的 import、變數與方法；提交前清掉 `console.log`、假資料與暫存程式碼。
    

### Code Review 要點

來源：CLN前端CR工具0630版／cln-code-review-instructions.md

送 CR 前先依[開發規範](#web-rules)自查共通實作方式；本節不重複列出 `noblank`、`disabled`、`lip-inputNumber`、`th scope`、toast／重查與成員順序，並聚焦 AI 輔助流程、規格一致性及依檔案類型整理的檢查表。

### AI 輔助 CR 工具怎麼用

### 載入檢查要點

在 VS Code 開啟 `cln-code-review-instructions.md`，對 AI 下指令（建議 Ask 模式）：「請閱讀和執行此檔」。

### 規格書轉成 md

把規格書 Word 檔放進工具的 `input` 資料夾，執行後到 `output` 取 md 檔。前端規格書用「Angular規格書轉md-v2」（run.bat），後端用「word-to-markdown-converter」（exe）；用錯工具會遺失內容。

### 附上檔案並執行 CR

開啟要 CR 的程式檔與上面兩個 md，用 chat 左下角「+」→ Open Editors 加入附件（Codex 則用「copy relative path」逐一貼上），下指令：「請依照上一題所理解的指示檔進行 code review」。

工具與操作說明在 `CLN前端CR工具0630版 1/` 資料夾。AI 會列出每個問題的行數與正確示範，全部列完後回覆「Code Review結束」。

### 畫面與元件（component.html）

| 檢查項目 | ✓ 這樣寫 | ✗ 不要這樣 |
| --- | --- | --- |
| 路由頁麵包屑 | `function-id-auth-map.ts` 用完整 path 當 key，例如 `/cln/case/caseinit` | 只用模組內的 path（`caseinit`） |
| 元件／資料夾名稱 | `cln-review-committee001` | `cln-review-committee-001`（數字前加 -） |
| 上行 LinkFrom | 值與元件名稱相同 | 名稱格式不一致 |
| h1 標題 | 外層 div 加 `mb-16` | 標題沒有下方間距 |
| p-card 間距 | 下方還有元件時 `styleClass="mb-32"` | 卡片之間沒有間距 |
| 按鈕間距 | 底部置中按鈕與上方距 32px；按鈕之間 16px，表格內 8px | 間距不一致 |
| 樣式 | `class="cub-text-center"` | `style="text-align: center;"`、沒有定義的無用 class |
| 頁籤 | 頁籤多才包 `cub-nav-tab-scroll`，並把子畫面包進 `cln-card-in-scroll-tab` | 頁籤少也包滾動；包了卻沒加 `cln-card-in-scroll-tab`（卡片兩側被裁切） |
| 金額 | td 加 `cub-text-right`，`| number:"1.0-0" | noblank` | 沒有靠右、沒有千分位 |
| 日期 | `| date:'yyyy/MM/dd' | noblank` | 直接顯示原始字串 |
| 百分比 | `| percentPipe | noblank` | 把「%」塞進 FormControl 的值 |
| 代碼轉文字 | `| rdCommonCodePipe: 'CODE_TYPE' | translate | noblank` | 在 ts 自己比對 value 找 label |
| p-card 唯讀欄位 | label 加 `cln-card-label`，顯示值 div 加 `cln-card-content` | 沒加 class，樣式不一致 |
| textarea | 加 `fixAutoResizeTextarea`（自動調整高度） | 固定高度的 textarea |
| 彈窗表格內的下拉 | `[appendTo]="'body'" panelStyleClass="cln-modal-select-panel"` | 不加，選單被表格遮住 |
| 案件編號欄位 | `<app-cln-comm-applyid (applyIdChange)="applyIdChangeQuery($event)">` | 自己刻一個只有案件編號的 p-card |
| undefined 風險 | 取值前確認物件存在（模板可用 `?.`） | 直接取可能為 undefined 的屬性 |

```
  <div class="cub-input-container">

    <div class="cln-card-content">{{ InputInfo.get('BorrowId').value | noblank }}</div>
  </div>

<!-- 金額 -->
<td class="cub-text-right">{{ report.get('AnnualIncome').value | number:"1.0-0" | noblank }}</td>
<!-- 日期 -->
<div class="cln-card-content">{{ rejectForm.get('InputDate').value | date:'yyyy/MM/dd' | noblank }}</div>
<!-- 代碼轉文字 -->
<div class="cln-card-content">{{ rejectForm.get('ApplyProcess').value | rdCommonCodePipe: 'APPLY_PROCESS' | translate | noblank }}</div>
<!-- textarea -->
<textarea pInputTextarea fixAutoResizeTextarea placeholder="請輸入" [attr.rows]="2" formControlName="LoanPosNote"></textarea>
```

### 程式、表單與服務（component.ts／service.ts）

| 檢查項目 | ✓ 這樣寫 | ✗ 不要這樣 |
| --- | --- | --- |
| 生命週期介面 | 用了 ngOnInit 就 `implements OnInit` | 有方法但沒 implements |
| 註解 | 全域變數、方法上方加 `/** 說明 */` | 沒註解（constructor、生命週期可省略） |
| 命名 | 小寫駝峰、看得懂用途 | `data1`、`temp` 這類無意義名稱 |
| 可選串連 | ts 用 `a && a.label`（TypeScript 3.5.3） | ts 裡寫 `a?.label` |
| 注入的服務 | html 有用到 `public`，沒用到 `private` | 可見性與用途不符 |
| 方法設計 | 重複邏輯抽共用，先找 `src/app/shared` | 方法裡再宣告方法；複製貼上相同邏輯 |
| 表單顯示值 | 值保持乾淨，顯示交給 pipe | 把「%」「第 期起」塞進 FormControl 的值 |
| 身分證 ID | `idCheckValidator(this.caseService)`，錯誤訊息用 `getError('invalidId')?.message` | 自己寫 ID 檢核與訊息 |
| 日期進 p-calendar | API 字串先轉成 `Date` | 直接塞字串 |
| 日期當上行 | `datePipe.transform(值, 'yyyy-MM-dd')` | 用「/」串接或直接傳 Date |
| 代碼選項 | `getComnCodeOptionsByCodetype()` + `mapToOptions`，多個用 `forkJoin` | 自己組 label／value |
| 錯誤處理 | 交給 ErrorInterceptor；要看 RETURNCODE 才加 `msgHidden` | subscribe 裡寫 error |
| 連續呼叫 | `pipe(switchMap(...))` | subscribe 裡再包 subscribe |
| 解訂閱 | Observable、Subject 要解訂閱 | 彈窗 ref、單純呼叫 API 也加 `takeUntil`（不需要） |
| 案件編號查詢 | 有案件編號查詢列時實作 `applyIdChangeQuery` 接收 applyId | 畫面自己 get／set sessionStorage 的 applyId |
| 導頁帶 applyId | 先 `sessionStorage.setItem('applyId', …)` 再導頁；`window.open` 同一案件則不用 | 把 applyId 放在路由參數 |
| 導頁帶其他參數 | 目的頁取完值執行 `router.navigateByUrl(router.url.split('?')[0])` | 網址保留參數（可被竄改、選單比對失敗） |
| component.scss | 只保留 HTML 有用到的樣式 | 留下無用 scss |
| service.ts | 全域變數 → constructor → 方法；共通命名與型別規則依[開發規範](#web-rules) | 呼叫 API、開彈窗的訂閱也去解訂閱（不需要） |
| interface | 名稱在同檔與整個專案都唯一 | 重複名稱的 interface |
