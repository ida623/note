# 後端共通規範

## 後端共通規範｜適用所有後端模組

來源：cln規格／CLN開發注意事項.pdf【後端】

各模組章節描述的是程式現況；新寫或修改後端程式時，依這裡的規範。依主題分成 6 組。

## 分支與本機環境

-   新交易有改到 `lip-svc-common-core` repo 時，從 `develop/dev-UT2` 切新分支開發，並用「lip-svc-common-core 2.0」CI/CD 腳本部署到 UT。
    
-   另外 clone `lip-svc-redis-manager`（分支 `develop/dev-cleanCache`）。某些交易方法要先啟動它才拿得到資料。
    
    它每 8 小時會自動清掉快取，之後需要重啟。
    
-   SQL 檔有異動，記得清**本機** Redis。
    
    UT 環境的快取另外清，步驟見「共通開發須知 → [2.4 常見問題與排除方式](%E5%85%B1%E9%80%9A%E9%96%8B%E7%99%BC%E9%A0%88%E7%9F%A5.md#devnotes-2-4)」。
    
-   本機（地端）可以用 `switch-user.properties`（lip-svc-cln 的 resources/config 下）設定要測試的員編與分行。
    
    怎麼找到有權限的員編，見「共通開發須知 → [2.5 開發與測試前置檢查](%E5%85%B1%E9%80%9A%E9%96%8B%E7%99%BC%E9%A0%88%E7%9F%A5.md#devnotes-2-5)」。
    
-   專案起不來、底層（lip-lib-cln-common）不是最新時，重新拉底層：
    
    方法一：對起不來的那包做 Maven update（clean + install）。  
    方法二：刪掉 `D:\Users\八碼員編\.m2\repository\cub\lip` 底下的 `lip-lib-cln-common`，再 Maven update，會重新抓最新底層到 .m2。  
    方法三：底層確定是新的、但專案指不到時：Maven setting → Local repository 的 Override 打開 → 那包做 Maven update（clean + install）→ 再把 Override 關閉。
    

## 交易寫法

-   交易上下行（Tranrq／Tranrs）的參數型別**一律為 String**。
    
-   一支 Service 裡面只寫一個方法（一支電文對一支 Service）。
    
-   上下行使用 `RequestTemplate`／`ResponseTemplate` 處理 MWHEADER。
    
-   回傳用 `normalRespFactory.genNormalResponse(...)`；回傳的是 `ResponseTemplate<EmptyDto>` 時用 `responseFactory.genEmptyResponse(...)`。
    
-   呼叫結果不是 `0000`，一律丟 `RestException`。
    
-   寫新交易要更新 EndPoint 資料表 `LON_ENDPOINT`，B 層與 C 層建在同一張表。**有建 ENDPOINT，Swagger 才打得到 API。**
    
    例：  
    `LIP-C-CLNITEMSC001`｜lip-svc-cln｜`/api/management/itemsetting/query`｜項目設定查詢  
    `LIP-B-CQYITEMSQ001`｜lip-svc-cln-query｜`/management/itemsetting/query`｜項目設定查詢  
    （欄位依序為 MSG\_ID、REPO\_NAME、URL、SERVICE\_NAME）
    
-   建立 DataProcessor 控制同一支交易的所有異動，方法加 `@Transactional(rollbackFor = Exception.class)`。
    
    與 Transaction 模組章節的 DataProcessor 寫法一致；外部服務的副作用不會跟著 rollback。
    

## 資料存取與 SQL

-   單表查詢與新增／刪除／修改用 **JPA 方法**，不要用 JPQL；多表查詢用 `SqlAction`。
    
-   SQL 撰寫格式：
    
    語法（select、from、where…）一律小寫；Table 名稱、欄位、別名一律大寫；傳入參數一律大駝峰（如 `:ApplyId`）；除了第一行，每行開頭空一格；多個比較條件要換行與縮排。
    
-   SQL 檔名用 `static final` 宣告。
    

#### SQL 檔範例（專案現有檔案）

```
-- lip-svc-cln-query/src/main/resources/sql/CQYFORMSQ001_query_002.sql
select *
 from LONLXLIP01CLN.CLN_RATING_DATA
 where APPLY_ID = :ApplyId
     [and BORROW_ID = :CustomerId]
 and IS_VALID = '1'
 and (SCORE_TYPE in ('G', 'C') or (SCORE_TYPE = 'S' and STATUS = '3'))
 order by CRED_DATE desc fetch first 1 row only
```

#### SQL 檔名宣告（專案現有寫法）

```
// lip-svc-cln-query/.../util/ReturnCodeAndDescUtil.java
private static final String SQL_GET_RETURN_CODE_DESC_001 =
        "ReturnCodeAndDescUtil.getReturnCodeDesc.sql";
```

範例中用 `[ ]` 包住的條件在專案裡很常見，看起來是「有傳參數才帶入」的選填條件；實際規則請以 SqlAction 的說明為準。

## 程式風格

-   多使用 StringUtil 與 stream 方法。
    
-   Class、方法與全域變數都要加 JavaDoc；`@Override` 的方法不用。
    
-   變數要用到才宣告，不要預先集中宣告在方法最上方。
    

## 測試報告

-   [ ] 寫 JUnit 單元測試，覆蓋率 100%。
-   [ ] PMD 全綠、SonarLint 沒有任何問題。
-   [ ] 附上交易正向與負向測試截圖。
-   [ ] 新交易已更新 LON\_ENDPOINT；SQL 有改已清本機 Redis 與 UT 快取。

### 單元測試檔放哪裡

**B 層**

在類別上 Alt + Enter 建立測試檔後，先在原本的資料夾跑測試。測完把 svc.impl 資料夾刪掉，再把 Test 檔移到 impl 底下。移過去之後就不能 run 方法了。

**C 層**

Alt + Enter 建立測試檔後，直接在原資料夾測試即可，測完不用搬位置。

## 開發完怎麼測：用 Swagger 打 API

先確認 LON\_ENDPOINT 已建好。Controller 改完重啟後，API 會自動出現在 Swagger 上；先測 B 層，再測 C 層。各服務 Swagger 網址見「共通開發須知 → 開發環境與本機服務入口」。

#### 先測 B 層：不用 Token

到對應服務（如 query 8081）的 Swagger 找到 API，直接帶電文測試。

```
// LIP-B-CQYIMAGEQ001 影像連結
{
  "MWHEADER": {
    "MSGID": "LIP-B-CQYIMAGEQ001",
    "SOURCECHANNEL": "LON-LX-LIP-01",
    "TXNSEQ": "202654789"
  },
  "TRANRQ": {
    "ApplyId": "CL18380025101382"
  }
}
```

#### 再測 C 層：要先拿 Token

lip-svc-cln（8080）Swagger 找 `GET /token/get`（取得測試用 Token）→ Execute → 用複製圖示複製 Token → 右上角鎖頭圖示貼上 → Authorize → 關閉視窗，授權完成，再找 API 測試。

```
// LIP-C-CLNIMAGEC001 影像連結
{
  "MWHEADER": {
    "MSGID": "LIP-C-CLNIMAGEC001",
    "SOURCECHANNEL": "LON-LX-LIP-01",
    "TXNSEQ": "202654789"
  },
  "TRANRQ": {
    "Type": "VIEW",
    "ApplyId": "CL18380025101382"
  }
}
```
