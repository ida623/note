以下照 Angular v17 時期的官方教學「英雄之旅」（Tour of Heroes）走，現行 angular.dev 已改用別的入門教學，原文在 v17 的存檔文件[出處](https://v17.angular.io/tutorial/tour-of-heroes)。原文用 NgModule，這裡改用 standalone 寫法。

```

```

確認根元件能顯示標題，再清掉產生器附帶的示範內容。教學原文以 `AppModule` 啟動；standalone 寫法對應到 `bootstrapApplication` 與 `app.config.ts`。

*【Step 2，英雄編輯器】*

## 建立 Hero 型別並雙向編輯名稱

```
export interface Hero {
  id: number;
  name: string;
}

hero: Hero = { id: 1, name: '疾風俠' };
```

```
<h2>{{ hero.name | uppercase }} 詳細資料</h2>
<label>
  名稱：
  <input [(ngModel)]="hero.name" placeholder="英雄名稱">
</label>
```

元件的 `imports` 要加 `FormsModule` 才能用 `ngModel`。內建管道（pipe）整包匯入 `CommonModule` 可行，但 standalone 元件也可以只匯入用到的那個管道（如 `UpperCasePipe`），打包更精準[出處](https://angular.dev/guide/templates/pipes)。

*【Step 3，顯示清單】*

## 列出英雄並選取一位

```
@for (hero of heroes; track hero.id) {
  <button
    [class.selected]="hero.id === selectedHero?.id"
    (click)="select(hero)">
    <span>{{ hero.id }}</span> {{ hero.name }}
  </button>
}
```

穩定的英雄 ID 讓 Angular 重用 DOM；點擊只更新選取狀態，頁面不重載——〈指令與資料綁定〉的 `track` 與事件綁定在這裡合體。

*【Step 4，拆出詳細資料元件】*

## 責任拆分，不是搬 HTML

```
@Component({
  selector: 'app-hero-detail',
  standalone: true,
  imports: [FormsModule],
  templateUrl: './hero-detail.component.html'
})
export class HeroDetailComponent {
  @Input() hero?: Hero;
}
```

```
<app-hero-detail [hero]="selectedHero" />
```

父元件管清單與選取狀態，詳細資料元件經 Input 接英雄。這一步的重點是責任拆分：誰擁有狀態、誰只負責呈現。

*【Step 5，建立服務】*

## 資料取得移出元件

```
@Injectable({ providedIn: 'root' })
export class HeroService {
  getHeroes(): Observable<Hero[]> {
    return of(HEROES);
  }
}
```

```
heroes: Hero[] = [];

ngOnInit(): void {
  this.heroService.getHeroes()
    .subscribe(heroes => this.heroes = heroes);
}
```

服務像資料櫃台：元件只提需求，不管資料現在是寫死的陣列、記憶體模擬還是真正的後端。之後換資料來源，元件一行都不用改。

*【Step 6，新增導覽】*

## Dashboard、Heroes 與 Detail 路由

```
export const routes: Routes = [
  { path: '', redirectTo: '/dashboard', pathMatch: 'full' },
  { path: 'dashboard', component: DashboardComponent },
  { path: 'heroes', component: HeroesComponent },
  { path: 'detail/:id', component: HeroDetailComponent }
];
```

```
export const appConfig: ApplicationConfig = {
  providers: [provideRouter(routes)]
};
```

```
<h1>英雄之旅</h1>
<nav>
  <a routerLink="/dashboard">儀表板</a>
  <a routerLink="/heroes">英雄清單</a>
</nav>
<router-outlet />
```

詳細頁從 `ActivatedRoute` 讀 `id`，再請服務拿英雄。教學原文把 `RouterModule.forRoot(routes)` 放進 NgModule；standalone 寫法改由 `provideRouter(routes)` 提供。`pathMatch: 'full'` 表示整段路徑完全相符才轉址，空路徑的轉址一定要配它。

*【Step 7，從伺服器取資料】*

## HttpClient、刪除與搜尋

```
export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient()
  ]
};
```

```
private heroesUrl = 'api/heroes';

getHeroes(): Observable<Hero[]> {
  return this.http.get<Hero[]>(this.heroesUrl)
    .pipe(catchError(() => of([])));
}

deleteHero(id: number): Observable<unknown> {
  return this.http.delete(`${this.heroesUrl}/${id}`);
}

searchHeroes(term: string): Observable<Hero[]> {
  const value = term.trim();
  return value
    ? this.http.get<Hero[]>(`${this.heroesUrl}/?name=${value}`)
    : of([]);
}
```

教學用 `angular-in-memory-web-api` 模擬伺服器：安裝後在 `app.config.ts` 設定，它會在瀏覽器端攔截 HTTP 請求、回傳假資料，讓你沒有後端也能練完整的增刪改查；正式產品改接真正的 API。這個套件與各 Angular 版本的相容性、standalone 的設定細節，動手前照套件目前的文件確認。

搜尋輸入交給 RxJS 的 `Subject<string>`（一種可以手動塞值進去的 Observable；Observable 是 RxJS 的資料流物件，值會陸續送來、要訂閱才拿得到），再串三個運算子：`debounceTime(300)` 等使用者停頓 300 毫秒才動作、`distinctUntilChanged()` 忽略跟上次相同的字串、`switchMap` 一有新搜尋就改訂最新的請求，舊請求的結果不會蓋掉新的。

```
private searchTerms = new Subject<string>();

heroes$ = this.searchTerms.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(term => this.heroService.searchHeroes(term))
);

search(term: string): void {
  this.searchTerms.next(term);
}
```

`searchTerms` 是元件內部實作，設 private；`heroes$` 要在樣板搭配 `async` 管道使用，所以保持可存取。名稱結尾的 `$` 是「這是 Observable」的命名慣例，不是 TypeScript 語法。

*【完成檢查】*

## 沿著使用者流程驗收

*   從儀表板能進到英雄詳細頁。
*   英雄清單能選取、新增、修改與刪除。
*   重新導覽後，路由參數仍載入正確的英雄。
*   搜尋會等使用者停手才送出，且舊請求不會覆蓋較新的結果。
*   HTTP 錯誤有可理解的處理方式。
*   正式建置與測試都通過。

### 重點整理

*   七步依序練：骨架、雙向編輯、清單、子元件、服務、路由、HTTP。
*   standalone 把舊 NgModule 的設定拆到元件 `imports` 與應用程式層 providers。
*   資料取得放服務，元件不管來源是假資料還是真後端。
*   搜尋資料流的三個運算子：`debounceTime` 等停手、`distinctUntilChanged` 略過重複、`switchMap` 只留最新。

**Q1. 英雄編輯器要用 [(ngModel)]，standalone 元件需要什麼？**

- (A) 在元件 imports 加入 FormsModule
- (B) 先建立 AppModule 並宣告元件
- (C) 在 providers 註冊 provideRouter
- (D) 把輸入框改成 ng-template

<details><summary>看答案</summary>

**答案：(A)** ngModel 由 Angular Forms 提供；standalone 元件自己 imports，不需要 AppModule。

</details>

**Q2. 顯示英雄清單時，最合適的 track 值是什麼？**

- (A) hero.id
- (B) $index，不管清單怎麼變動
- (C) hero.name（名稱可能重複或改名）
- (D) 每次渲染時產生的隨機值

<details><summary>看答案</summary>

**答案：(A)** track 要穩定且唯一：索引在增刪時錯位、名稱會變、隨機值每次都不同。

</details>

**Q3. Step 4 把詳細資料拆成子元件，主要價值是什麼？**

- (A) 責任拆分：父元件管狀態，子元件負責呈現與編輯單一英雄
- (B) 減少 HTTP 請求次數
- (C) 讓樣式自動穿透到子元件
- (D) 避免使用 Input 與 Output

<details><summary>看答案</summary>

**答案：(A)** 拆元件是為了清楚的擁有權與重用性，不影響請求數，也正是靠 Input/Output 溝通。

</details>

**Q4. HeroService 的角色是什麼？**

- (A) 封裝英雄資料的取得，讓元件不管資料來源
- (B) 集中管理所有元件的 CSS

- (D) 把樣板編譯成 DOM

**Q7. 搜尋流程中 switchMap 的價值是什麼？**

- (A) 新搜尋出現時改訂最新的請求，舊請求結果不會蓋掉新的
- (B) 把多次搜尋的結果全部合併保留
- (C) 保證每次搜尋都命中快取
- (D) 把字串轉成大寫再送出

<details><summary>看答案</summary>

**答案：(A)** switchMap 退訂舊的內層 Observable，避免慢的舊回應覆蓋快的新結果；要全部保留是 mergeMap。

</details>

**Q8. debounceTime(300) 在搜尋框上的作用是什麼？**

- (A) 等使用者停止輸入 300 毫秒才發出搜尋
- (B) 把回應延遲 300 毫秒再顯示

- (D) 限制搜尋字串最長 300 字

<details><summary>看答案</summary>

**答案：(A)** 連續敲鍵不送出，停頓才動作，省下大量無效請求。

</details>

<details><summary>看答案</summary>

**答案：(A)** 它是教學與原型用的模擬伺服器；正式產品要改接真正的 API。

</details>
