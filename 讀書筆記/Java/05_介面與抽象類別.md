# 05. 介面與抽象類別

> 來源：[筆記平台 · Java](https://hhtim.github.io/notes-platform/java/#/lesson/interfaces-abstract)　第 5 課 / 共 18 課 · 約 11 分鐘

**抽象類別共用骨架、介面約定能力，兩者怎麼選，以及 Java 8 之後介面變了什麼。**

### 讀完這課你會

- 說明抽象類別與抽象方法各自在解決什麼問題
- 判斷什麼時候用 `extends`、什麼時候用 `implements`
- 知道 Java 8 之後介面多了什麼
- 用「依賴規格而不是依賴實作」的寫法降低耦合

---

*【先建立觀念】*

## 抽象類別是不能直接用的半成品

「動物」是一個概念，真正存在的是狗、鳥、魚。程式裡也可以用抽象類別（abstract class）表示這種概念：先把子類別共有的資料與行為整理好，把還沒決定的細節留給子類別完成。可以把它想成一份**範本**，因為只是範本，所以不能直接拿來建立物件。

```java
abstract class Pen {
    private final String brand;

    protected Pen(String brand) {   // 抽象類別可以有建構子
        this.brand = brand;
    }

    public String getBrand() {      // 也可以有寫好的一般方法
        return brand;
    }

    public abstract void write();   // 抽象方法：沒有大括號
}

class Pencil extends Pen {
    Pencil(String brand) {
        super(brand);
    }

    @Override
    public void write() {
        System.out.println("用石墨書寫");
    }
}
```

抽象方法沒有方法主體，連 `{ }` 都拿掉。兩條規則要記住：**只要類別裡有抽象方法，這個類別就一定要宣告成抽象類別**；但反過來不成立——抽象類別不一定要有抽象方法，有時候只是設計者刻意不讓別人直接建立它的物件。

> 抽象類別不能建立物件，那它的建構子做什麼用？給子類別透過 `super(...)` 呼叫，負責初始化共同的那一段。

---

*【繼承之後的責任】*

## 具體子類別必須補齊所有抽象方法

子類別繼承抽象類別後，如果沒把所有抽象方法補完，它自己也只能是抽象類別。一路補到某個子類別把欠的都做完，才成為可以建立物件的**具體類別**（concrete class）。

從語法看，把抽象方法寫完就是覆寫；語意上大家習慣叫它「實作」——因為原本那個方法根本沒有內容，是從無到有做出來的。

```java
Pen pen = new Pencil("ABC");
pen.write();   // 執行 Pencil.write()
```

變數的型別是 `Pen`，實際物件是 `Pencil`，執行時按真正的物件挑方法——這就是〈封裝、繼承、多型〉講的動態繫結。**抽象類別不能建立物件，不代表它不能當變數的型別。**

---

*【行為契約】*

## 介面像插座規格：只約定怎麼接

介面（interface）用來定義一組能力。鳥、飛機跟超人沒有現實上的「是一種」關係，卻都會飛，所以都能實作同一個 `Flyable`。介面的用途可以列成五項：多重繼承、定義規格、貼標籤、型別轉換、降低相依性。

```java
interface Flyable {
    int MAX_HEIGHT = 10_000;   // 自動是 public static final，宣告時就要給值
    void fly();
}

class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("拍動翅膀飛行");
    }
}
```

介面裡直接宣告的欄位隱含是 `public static final`，也就是大家共用的常數，所以一定要給初始值。介面沒有建構子，也不能建立物件，但跟抽象類別一樣可以當參考型別。

---

*【介面的新成員】*

## Java 8 之後，介面不再只有抽象方法

「介面裡的方法一律是抽象方法」已經是 Java 8 以前的答案。Java 8 起介面可以有帶實作的 `default` 方法與 `static` 方法，Java 9 起還能有 `private` 方法 [[出處]](https://docs.oracle.com/javase/tutorial/java/IandI/defaultmethods.html) [[出處]](https://openjdk.org/jeps/213)。

```java
interface Greeter {
    String name();

    default String greet() {          // Java 8：有預設實作，實作類別可以不寫
        return "Hello, " + name();
    }

    static Greeter of(String n) {     // Java 8：介面自己的工具方法
        return () -> n;
    }
}
```

為什麼要加 `default`？因為以前只要往一個已經上線的介面加方法，所有實作它的類別就全部編譯不過。有了預設實作，介面才能在不弄壞既有程式的前提下長大。

> 💡 **現在只有「沒寫方法主體」的介面方法才隱含 `public abstract`——寫了主體的不是**

---

*【組合能力】*

## 類別只能單一繼承，卻能實作多個介面

Java 類別只能直接繼承一個父類別，但可以同時實作多個介面。這不是繼承好幾份狀態，而是「這個物件承諾具備這幾種能力」。

> 💡 **`class 子類別 extends 父類別 implements 介面一, 介面二`**

```java
interface Writable { void write(String text); }
interface Erasable { void erase(); }

class SmartPen extends Pen implements Writable, Erasable {
    SmartPen(String brand) { super(brand); }

    @Override public void write() { write("預設內容"); }
    @Override public void write(String text) { System.out.println(text); }
    @Override public void erase() { System.out.println("清除筆跡"); }
}
```

介面跟介面之間用 `extends` 延伸，而且**一個介面可以延伸多個介面**。口訣：類別繼承類別用 `extends`，類別履行介面用 `implements`。

---

*【多型設計】*

## 依賴介面，使用端就不必綁死實作

如果一段流程只需要「會寫字」這個能力，參數就宣告成 `Writable`，不要指定鉛筆、鋼筆或毛筆。像物流中心只要求箱子符合輸送帶尺寸，不必知道箱子裡裝什麼。

```java
class WritingService {
    void publish(Writable tool, String text) {
        tool.write(text);
    }
}
```

之後新增工具只要實作 `Writable`，`WritingService` 通常一個字都不用改。這牽涉到兩個詞：相依性（耦合，coupling，一個類別有多依賴另一個具體類別）要低，凝聚性（內聚性，cohesion，一個類別的職責有多集中）要高。

---

*【特殊用途】*

## 空介面只負責貼標籤

沒有宣告任何方法的介面叫空介面，或標記介面（marker interface）。它不要求你多做什麼，只是替型別貼一個標籤，讓 Java 或框架認得出來。最有名的兩個是 `java.io.Serializable`（可以序列化）與 `java.lang.Cloneable`。

**實作 `Cloneable` 本身**不會**讓物件變得可複製——它只是讓 `Object.clone()` 不要丟 `CloneNotSupportedException`。真要複製，還得自己覆寫 `clone()` 並把它開放出來，而且 `Object.clone()` 做的是淺層複製（內部的物件還是共用的）** [[出處]](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Cloneable.html)。同理，實作 `Serializable` 只是取得入口資格，不保證每一種操作都會成功。

> 📝 原筆記更正：原筆記寫「一個類別implements前者java.lang.Cloneable空介面時，該類別的物件才可以做物件的複製」，查證後更正：實作 Cloneable 只是讓 Object.clone() 不丟 CloneNotSupportedException，還得自己覆寫並開放 clone() 才真的複製得到

*【選擇指南】*

## 抽象類別與介面怎麼選

| 比較項目 | 抽象類別 | 介面 |
|---|---|---|
| **核心關係** | 同一家族的「是一種」 | 跨家族的「具備某能力」 |
| **能不能建立物件** | 不能 | 不能 |
| **實體狀態** | 可以有實體欄位 | 直接宣告的欄位都是常數 |
| **建構子** | 有，供子類別呼叫 | 沒有 |
| **一個類別能用幾個** | 只能繼承一個 | 可以實作多個 |
| **適合什麼** | 共用狀態、基礎流程與部分實作 | 定義契約、替換實作、降低耦合 |

沒有「介面永遠比抽象類別好」這種答案。看關係自不自然：有共同狀態跟建構流程就用抽象類別；跨越不同家族的共同能力就用介面。兩者也常常一起用——抽象類別保存共同狀態，介面把對外能力定成穩定的契約。

### 重點整理

- 抽象類別不能建立物件，但可以有建構子、欄位與寫好的一般方法。
- 有抽象方法的類別一定要是抽象類別；抽象類別不一定要有抽象方法。
- 類別只能繼承一個父類別，卻能實作多個介面；介面之間也能互相延伸。
- Java 8 起介面可以有 default 與 static 方法，Java 9 起還有 private——「介面方法一律抽象」已是舊答案。
- 介面欄位隱含是 `public static final`；介面沒有建構子，但可以當參考型別。
- 空介面只貼標籤；實作 `Cloneable` 不等於自動就複製得了。

## 隨堂測驗

**Q1. 關於抽象類別，哪一項正確？**

- (A) 一定要至少有一個抽象方法
- (B) 所有欄位一定都是常數
- (C) 不能被當成變數的宣告型別
- (D) 不能直接建立物件，但可以有建構子、欄位與一般方法

<details><summary>看答案</summary>

**答案：(D)** 抽象類別把還沒決定的行為留給子類別，所以不能直接實體化；建構子則留給子類別用 super(...) 呼叫。

</details>

**Q2. 「介面裡的方法一律是抽象方法」這句話現在還成立嗎？**

- (A) 不成立，Java 8 起有 default 與 static，Java 9 起還有 private
- (B) 不成立，Java 5 起介面就能有實作
- (C) 成立，但只限於標記介面
- (D) 成立，任何版本的介面都只能有抽象方法

<details><summary>看答案</summary>

**答案：(A)** Java 8 引入 default 與 static 方法，Java 9 再加上 private 方法；只有沒寫方法主體的才隱含 public abstract。

</details>

**Q3. 介面新增 default 方法，最主要是為了解決什麼問題？**

- (A) 讓類別可以繼承多個父類別
- (B) 讓介面可以建立物件
- (C) 讓介面可以有實體欄位
- (D) 讓已經上線的介面可以加方法而不弄壞既有的實作類別

<details><summary>看答案</summary>

**答案：(D)** 以前往介面加方法，所有實作類別都會編譯失敗；有了預設實作，介面才能在不破壞相容性的前提下演進。

</details>

**Q4. 某類別要繼承 Device，又要具備 Rechargeable 與 Connectable 兩種能力，宣告該怎麼寫？**

- (A) extends Device, Rechargeable, Connectable
- (B) implements Device extends Rechargeable, Connectable
- (C) implements Device, Rechargeable extends Connectable
- (D) extends Device implements Rechargeable, Connectable

<details><summary>看答案</summary>

**答案：(D)** 類別用 extends 繼承唯一的父類別，用 implements 實作一個以上的介面。

</details>

**Q5. 介面中直接宣告的欄位，隱含帶有哪一組修飾子？**

- (A) protected static
- (B) public static final
- (C) private volatile
- (D) public transient

<details><summary>看答案</summary>

**答案：(B)** 介面欄位是公開、類別層級且不可重新指定的常數，所以宣告當下就要給值。

</details>

**Q6. 一個類別實作了 Cloneable，代表什麼？**

- (A) 物件自動就能被完整複製
- (B) 該類別自動可以被序列化
- (C) 所有欄位自動變成 final
- (D) 只是讓 Object.clone() 不丟例外，還要自己覆寫 clone() 才複製得到

<details><summary>看答案</summary>

**答案：(D)** Cloneable 是標記介面，本身沒有方法；真正的複製邏輯要自己覆寫 clone()，而且預設是淺層複製。

</details>

**Q7. 哪一種需求比較適合用介面而不是抽象類別？**

- (A) 彼此沒有共同父類別，但都要具備「可列印」能力的物件
- (B) 子類別需要共用的實體狀態
- (C) 建立物件時一定要跑的初始化流程
- (D) 一群員工共同擁有的姓名與到職日欄位

<details><summary>看答案</summary>

**答案：(A)** 介面描述跨越類別家族的共同能力；共同狀態與建構流程屬於抽象類別的地盤。

</details>

**Q8. Pen pen = new Pencil(); pen.write(); 若 Pencil 實作了抽象方法 write()，會執行哪個版本？**

- (A) 編譯錯誤，抽象類別不能當變數型別
- (B) 抽象類別 Pen 的空方法
- (C) 兩個版本都執行
- (D) Pencil 的 write()

<details><summary>看答案</summary>

**答案：(D)** 實體方法採動態繫結，看執行期的實際物件；抽象類別不能實體化，但完全可以當參考型別。

</details>
