*【先描述位置】*

## 建立 File 物件不等於建立硬碟上的檔案

`java.io.File` 是「檔案或目錄路徑」的物件表示。呼叫它的建構子只是在記憶體裡做一張**地址卡**，不會去建立、刪除或讀寫任何實體檔案——那個檔案可以早就存在，也可以之後才建。

```java
File directory = new File("data");
File report = new File(directory, "report.txt");   // 父目錄物件 + 子檔名

System.out.println(report.getPath());
System.out.println(report.getName());
System.out.println(report.exists());
```

| 方法 | 用途 |
|---|---|
| **`exists()`** | 路徑存不存在 |
| **`isFile()` / `isDirectory()`** | 是檔案還是目錄 |
| **`list()` / `listFiles()`** | 列出目錄內容（名稱陣列 / File 物件陣列） |
| **`length()`** | 檔案長度，只對檔案有效 |
| **`mkdir()` / `mkdirs()`** | 建一層 / 連不存在的父層一起建 |
| **`delete()`** | 刪檔案或空目錄 |

> `list()` 與 `listFiles()` 只對目錄有效。回傳陣列的長度是 0，表示目錄裡沒有東西；但呼叫失敗、或目標根本不是可列出的目錄時，它們會回傳 `null`，直接拿去跑迴圈就會吃到 `NullPointerException` [[出處]](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/File.html#listFiles())。

> 另外，`File(File parent, String child)` 這個建構子的第一個參數收的是 `File` 物件。寫成 `new File("myDir", "myFile.txt")` 傳的是字串，走到的其實是另一個建構子；要用 `File` 版就得傳前一行建好的那個物件 [[出處]](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/File.html#%3Cinit%3E(java.io.File,java.lang.String))。

*【路徑觀念】*

## 絕對路徑從根開始，相對路徑從工作目錄開始

- **絕對路徑**：寫出完整位置，好認，但換電腦或換部署環境就要改。
- **相對路徑**：以程式目前的工作目錄為基準，容易跟著專案搬家，但你得清楚程式是從哪裡啟動的。
- **`.`**：目前目錄。在 Eclipse 裡，指的是專案資料夾。
- **`..`**：上一層目錄。

不同作業系統的分隔符號不一樣，不要把 `\` 或 `/` 寫死。用 `File` 的父子建構方式可以，用比較新的 `Path` 更好：

```java
Path path = Path.of("data", "report.txt");   // Java 11 起的寫法
Files.readString(path);
```

> Java 7 起還有 `java.nio.file` 這一套（`Path`、`Files`），錯誤訊息比較清楚、功能也多。新程式建議從 `Path` 開始，`File` 主要用在跟舊函式庫相接的時候。

*【資料的水管】*

## 輸入是讀進來，輸出是寫出去

資料流（stream）像單向水管：輸入流把資料從檔案、網路或記憶體送進程式，輸出流把程式的資料送到目的地。Java 傳統的輸入輸出（I/O，Input／Output）建在四個抽象父類別上：

| 單位 | 輸入 | 輸出 | 拿來處理什麼 |
|---|---|---|---|
| **位元組 byte** | `InputStream` | `OutputStream` | 圖片、壓縮檔、音訊等二進位資料 |
| **字元 char** | `Reader` | `Writer` | 文字 |

這四個都是抽象的，你只能用它們的子類別建立物件，但都可以拿父類別來做多型操作。

「一個 `char` 就是一個 Unicode 字元」在今天已經不成立。`char` 是 16 位元的 UTF-16 **編碼單位**，Unicode 的碼位到 U+10FFFF（超過一百萬個），像表情符號和部分罕用漢字這類補充字元，要用兩個 `char`（代理對，surrogate pair，前後兩個編碼單位合起來才代表一個字）才裝得下——所以 `"😀".length()` 會是 2 [[出處]](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Character.html#unicode)。

更重要的是：**位元組跟文字之間一定要有一個字元編碼（charset）做翻譯。**處理文字時把編碼寫清楚，不要靠環境的預設值。

位元組流之所以「處理中文有困難」，原因就在這裡：它只搬位元組、不懂編碼，中文要靠字元流搭配明確指定的字元編碼才處理得對。另一件相關但不同的事是**預設編碼**：Java 18 起，標準函式庫的預設編碼統一成 UTF-8，不再跟著作業系統跑，跨平台的亂碼問題少了很多。`System.out` 與 `System.err` 不在這個預設值的範圍內，這兩個串流的編碼由 `Console.charset()` 決定 [[出處]](https://openjdk.org/jeps/400)。不過明寫編碼仍然是好習慣——舊版本不是這樣，而且寫出來讀的人也比較安心。

*【正確讀到檔尾】*

## read() 的回傳值同時告訴你讀到多少

`read()` 回傳 `-1` 代表已經到資料流末端。讀進陣列時，回傳值是**這一次實際讀到的數量**——最後一輪很可能沒把陣列填滿。

```java
try (InputStream in = new FileInputStream("photo.jpg");
     OutputStream out = new FileOutputStream("photo-copy.jpg")) {

    byte[] buffer = new byte[8192];
    int count;

    while ((count = in.read(buffer)) != -1) {
        out.write(buffer, 0, count);   // 只寫 count 個，不是整個 buffer
    }
}
```

> 如果每次都寫出整個 `buffer`，最後一輪會把上一次殘留的資料也寫進檔案。這是複製檔案時很常見、而且不容易一眼看出來的錯誤。

*【一層一層加功能】*

## 低階流接媒體，高階流負責緩衝與轉換

這個疊法叫 I/O 鏈，規則三句話就講得完：

- **低階流**（節點資料流）直接接資料來源或目的地，例如 `FileInputStream`、`FileReader`，功能陽春。
- **高階流**（處理資料流）像套在水管外面的配件，提供緩衝、編碼轉換與更好用的方法，例如 `BufferedReader`。
- 建立時**一定要先有低階流**，再用高階流包住它；高階流之間也可以再疊。輸入只能接輸入，輸出只能接輸出。

```java
try (BufferedReader reader =
         new BufferedReader(
             new InputStreamReader(
                 new FileInputStream("notes.txt"),
                 StandardCharsets.UTF_8))) {

    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}
```

這條鏈由內往外讀：`FileInputStream` 接上檔案吐位元組 → `InputStreamReader` 照 UTF-8 把位元組解碼成字元 → `BufferedReader` 加上緩衝與 `readLine()`。`InputStreamReader` 這種角色叫**橋接類別**，專門把位元組體系接到字元體系。

**Buffered 系列與 `InputStreamReader` **包的是另一個資料流，不是 `File` 物件**：`BufferedReader`、`BufferedWriter` 收的是 `Reader`、`Writer`，`BufferedInputStream`、`BufferedOutputStream`、`InputStreamReader` 收的是 `InputStream`、`OutputStream`，中間一定要先有一個低階流。至於 `PrintStream`，它屬於位元組體系，包得了 `OutputStream`，就是包不了 `Writer`——字元體系那邊對應的是 `PrintWriter`** [[出處]](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/BufferedReader.html) [[出處]](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/PrintStream.html)。

> 📝 原筆記更正：原筆記（常用方法）的「File系列小總結」把緩衝流直接包在 File 物件上（fileIn、fileOut 都是 File），寫成 BufferedInputStream bis = new BufferedInputStream(fileIn); BufferedReader br = new BufferedReader(fileIn); BufferedOutputStream bos = new BufferedOutputStream(fileOut); BufferedWriter bw = new BufferedWriter(fileOut); 四行用 JDK 21 都編譯不過；另一行 PrintStream ps = new PrintStream(fo / fw); 只有 fw（FileWriter）那種編不過，fo（FileOutputStream）編得過。查證後更正

> 有幾個類別另外提供直接收 `File` 的便利建構子：`PrintStream(File)`、`PrintWriter(File)`、`Scanner(File)` 都編得過，它們是在內部先幫你建好低階流。這不推翻上面的規則，只是省掉一層括號。

*【文字輸出】*

## 覆寫、附加與 flush 是三件不同的事

```java
try (BufferedWriter writer =
         new BufferedWriter(
             new OutputStreamWriter(
                 new FileOutputStream("app.log", true),   // true = 附加
                 StandardCharsets.UTF_8))) {
    writer.write("服務啟動");
    writer.newLine();
}
```

`FileOutputStream` 與 `FileWriter` 的第二個參數是「要不要附加」：`true` 就接在原內容後面，**預設是 `false`，會把原檔整個蓋掉**。另外，這些建構子會幫你把檔案建出來，所以不必事先手動建立。

- **flush()**：把緩衝區裡的資料推往下一層，但資料流還開著。
- **close()**：關閉並釋放資源，關之前通常會先完成必要的輸出。

用 try-with-resources 之後這兩件事大多不必自己來。

*【標準輸入輸出】*

## System.in、System.out 與 System.err

| 資料流 | 型別 | 預設接哪 |
|---|---|---|
| **`System.in`** | `InputStream` | 鍵盤 |
| **`System.out`** | `PrintStream` | 螢幕，一般輸出 |
| **`System.err`** | `PrintStream` | 螢幕，錯誤訊息 |

這三個不用 `new` 就能用。Java 5 起要從鍵盤讀東西，用 `Scanner` 比自己疊 `InputStreamReader` ＋ `BufferedReader` 短很多：

```java
Scanner scanner = new Scanner(System.in);
System.out.print("請輸入年齡：");
int age = scanner.nextInt();
```

> 注意：關掉包著 `System.in` 的 `Scanner`，連底層的標準輸入一起關掉了，之後就再也讀不到鍵盤。整支程式共用一個時，要先想清楚誰是它的擁有者。

*【保存整個物件】*

## 序列化把物件狀態寫成位元組

序列化（serialization）就是把物件連同型別與欄位值變成一串位元組，好存成檔案或送過網路；把物件永久存起來這件事叫持久化（persistence）。`ObjectOutputStream` 負責寫出，`ObjectInputStream` 負責讀回，而且它們都是高階流——括號裡還要再傳一個低階流進去。

```java
class Profile implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private transient String sessionToken;   // transient 的不會被存
}

try (ObjectOutputStream out =
         new ObjectOutputStream(new FileOutputStream("profile.bin"))) {
    out.writeObject(new Profile());
}

try (ObjectInputStream in =
         new ObjectInputStream(new FileInputStream("profile.bin"))) {
    Profile profile = (Profile) in.readObject();   // 回傳 Object，要自己轉回來
}
```

幾條規則：要寫出的類別必須實作 `Serializable`（〈介面與抽象類別〉講過，這是個空介面，只是貼標籤）；父類別實作了，子類別等同也實作了；`readObject()` 回傳 `Object`，傳統寫法得自己轉型；**讀回來的順序要跟寫出去的順序一致**。標了 `transient` 的欄位不會被存，`static` 欄位屬於類別而不是個別物件，也不在物件狀態裡。

> 還有兩件事要知道：`serialVersionUID` 是類別的版本編號，不自己指定的話，類別稍微改一下舊檔案就讀不回來了；另外，**絕對不要反序列化來路不明的資料**——那等於讓對方決定你的程式要建立什麼物件，是很經典的攻擊面。Java 的序列化也不適合當跨語言的長期保存格式，那種需求請用 JSON 之類的。

### 重點整理

- `new File(...)` 只是做一張路徑地址卡，不會動到硬碟上的東西。
- 二進位資料用位元組流，文字用字元流，而且把編碼明寫出來。
- `char` 是 16 位元的 UTF-16 編碼單位，不等於一個 Unicode 字元。
- `read()` 回 `-1` 是檔尾；讀進陣列時要照回傳的數量處理，不要整個 buffer 寫出去。
- Buffered 系列與 `InputStreamReader` 包的是另一個資料流，不是 `File`；要先有低階流接上媒體。`PrintStream`、`PrintWriter`、`Scanner` 才有直接收 `File` 的便利建構子。
- 附加模式保留原內容，預設的非附加模式會蓋掉原檔。
- 序列化要實作 `Serializable`；`transient` 與 `static` 不會被存，來路不明的資料不要反序列化。
