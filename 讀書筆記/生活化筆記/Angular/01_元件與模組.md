## 元件（Component）是 Angular 的基本單位

> 🏠 **生活比喻**
>
> 把一個 Angular 網站想成**夜市**，每個元件就是一個**攤位**：
> - **樣板（Template）**＝攤位的招牌、擺設，客人眼睛看到的樣子。
> - **類別（Class）**＝老闆腦袋裡的事：今天剩幾份、客人點餐後要做什麼。
> - **樣式（Styles）**＝攤位的配色和裝潢，只裝飾自己這攤。
> - **中繼資料（Metadata）**＝攤位登記證：攤號叫什麼（selector）、要用哪些設備（imports）。
>
> 大到一整排攤位、小到一個試吃小桌，都可以是一個攤位（元件）。

Angular 應用程式由元件組成：大到一整頁、小到一顆按鈕，都能做成獨立元件。每個元件通常包含四個部分：

*   **樣板（Template）**：畫面的 HTML 結構。
*   **類別（Class）**：用 TypeScript 寫的狀態與行為。
*   **樣式（Styles）**：元件自己的 CSS、SCSS 或 Less。
*   **中繼資料（Metadata）**：寫在 `@Component` 裝飾器裡，說明選擇器、匯入項目與檔案位置。

```
import { Component } from '@angular/core';

@Component({
  selector: 'app-user-profile',
  standalone: true,
  templateUrl: './user-profile.component.html',
  styleUrl: './user-profile.component.css'
})
export class UserProfileComponent {
  userName = '王小明';

  onButtonClick(): void {
    console.log('按鈕被點擊了');
  }
}
```

建立元件可以用指令 `ng generate component user-profile`，或簡寫 `ng g c user-profile`。新版 CLI 產生的元件預設就是 standalone。

Angular 19 起 `standalone: true` 是預設值，可以不寫[出處](https://angular.dev/guide/components)；這裡寫出來是讓新舊寫法的差異一眼可見。

## standalone 與 NgModule

> 🏠 **生活比喻**
>
> - **standalone**＝**自助旅行**：自己的行李清單（imports）自己列，想帶什麼就寫什麼，不用跟誰報備。
> - **NgModule**＝**跟團旅行**：所有團員要先登記在旅行團名下，由旅行團統一安排。
>   - `declarations`＝團員名單（這團自己的人）
>   - `imports`＝向別的旅行團借導遊、借遊覽車
>   - `exports`＝本團開放給別團共用的資源
>   - `providers`＝團裡配的共用服務人員（像司機）
> - `bootstrapApplication`＝直接出發，不用先去旅行社（AppModule）報到。
>
> 跟團不是錯，只是比較舊式；老專案很多都是跟團行程，要看得懂。

standalone 元件像自己帶行李清單的旅客：需要哪些元件、指令或管道，直接列在自己的 `imports`，不必先登記到某個 NgModule。

```
@Component({
  standalone: true,
  imports: [UserCardComponent],
  template: '<app-user-card />'
})
export class HomeComponent {}
```

NgModule 則像傳統的功能包裹（模組容器），舊專案用它把相關的元件與相依項目集中組織。現代 Angular 官方建議所有新程式改用 standalone 元件；standalone 應用程式由 `bootstrapApplication` 直接啟動根元件，不需要 AppModule[官方建議](https://angular.dev/guide/ngmodules/overview)[standalone 啟動](https://angular.dev/reference/migrations/standalone)。維護既有專案時，下面四個 NgModule 屬性仍要看得懂：

> 📝 查證更正：原筆記寫「Angular 應用至少需要一個根模組（AppModule）」，查證後更正：那是 NgModule 時代的規則，standalone 應用程式不需要任何 NgModule

| 屬性 | 用途 |
| --- | --- |
| `declarations` | 宣告屬於這個模組的非 standalone 元件、指令與管道；同模組內可以互相使用。 |
| `imports` | 匯入其他模組或 standalone 項目，取得它們提供的功能。 |
| `exports` | 把自己的項目公開，讓匯入這個模組的一方使用。 |
| `providers` | 註冊服務，讓依賴注入系統可以取得。 |

```
@NgModule({
  declarations: [LegacyCardComponent],
  imports: [CommonModule],
  exports: [LegacyCardComponent],
  providers: [UserService]
})
export class SharedModule {}
```

NgModule 是舊寫法、不是錯誤寫法；既有專案很可能整包都是這個樣子。新專案通常改用 standalone 元件，服務註冊移到應用程式層級的 providers。

## 不留下外殼的 ng-container

> 🏠 **生活比喻**
>
> 像用**橡皮筋**把幾支筆綁成一束：筆被整理成一組了，但桌上沒有多出一個筆筒。
> `ng-container` 把多個元素綁在一起，畫面上卻不會多一層盒子（DOM 標籤）來佔位子、亂掉排版。

`ng-container` 像透明資料夾（邏輯容器）：能把多個節點包成一組，卻不會在頁面上產生真正的 DOM 元素，所以不會多出一層標籤去干擾版面或樣式。

```
@for (item of menuList; track item.id) {
  <ng-container>
    <a>{{ item.name }}</a>
    <span>{{ item.description }}</span>
  </ng-container>
}
```

*【先寫好、等著上場】*

## ng-template 與 ngTemplateOutlet

> 🏠 **生活比喻**
>
> `ng-template` 像**抽屜裡的印章**：先刻好，平常收著不會出現在紙上。
> `ngTemplateOutlet` 就是「**拿印章蓋在這裡**」這個動作；`context` 像印章上的空格「＿＿先生／小姐」，蓋的時候再填名字進去。

`ng-template` 像先搭好、還沒推上舞台的布景（樣板片段）：Angular 不會直接顯示它，必須由控制流程或 `ngTemplateOutlet` 把它實例化才會出現。`ngTemplateOutlet` 的 outlet 意思是「放置的出口」，看到 xxxOutlet 都可以想成「某個東西被放到這裡」，跟路由的 `router-outlet` 是同一種命名。

```
<ng-template #emptyState let-message="message">
  <p>{{ message }}</p>
</ng-template>

<ng-container
  *ngTemplateOutlet="emptyState; context: { message: '目前沒有資料' }">
</ng-container>
```

舊式的 `*ngIf`、`*ngFor` 這些結構型指令，會在編譯時展開成樣板；Angular 17 之後有了內建控制流程，新程式優先用 `@if`、`@for` 與 `@switch`（〈指令與資料綁定〉細講）。

```
@if (isLoggedIn) {
  <p>歡迎回來</p>
} @else {
  <p>請先登入</p>
}
```

## ng-content 內容投影

> 🏠 **生活比喻**
>
> 像**相框**：子元件是相框，決定外框和尺寸；父元件決定放哪張照片進去。
> - 多格相框的每一格貼了標籤（`select`），例如「這格放全家福」。
> - 如果照片外面套了一層透明袋（被 `ng-container` 包住），相框認不出它是全家福，就會被丟進「其他」那格。這時在照片上貼一張「我是全家福」的標籤（`ngProjectAs`）就解決了。

內容投影（Content Projection）像子元件預留插槽、由呼叫端決定塞什麼進去：子元件定版型，父元件供內容。

```
<!-- panel.component.html -->
<header><ng-content select="[panel-title]" /></header>
<main><ng-content /></main>

<!-- 使用元件 -->
<app-panel>
  <h2 panel-title>課程公告</h2>
  <p>今天開始學 Angular。</p>
</app-panel>
```

要投影的節點如果被額外的容器（例如 `ng-container`）包住，`select` 選擇器會配對不到，內容就掉進沒有選擇器的預設插槽。這時可以在該節點加 `ngProjectAs`，明確告訴 Angular 要把它當成哪種選擇器來配對。

*   **Component**：元件，負責一塊畫面與它的互動。
*   **Template**：樣板，描述元件的畫面結構。
*   **Content Projection**：內容投影，把父層準備的內容放進子元件的插槽。
*   **NgModule**：傳統的模組容器；standalone 架構下不再需要。

### 🗺️ 比喻對照表

| 技術名詞 | 生活比喻 |
| --- | --- |
| Component 元件 | 夜市的一個攤位 |
| Template / Class / Styles / Metadata | 招牌擺設 / 老闆的腦袋 / 裝潢 / 攤位登記證 |
| standalone | 自助旅行，自己列行李清單 |
| NgModule | 跟團旅行，由旅行團統一登記 |
| ng-container | 橡皮筋：綁成一組但不多一個筆筒 |
| ng-template / ngTemplateOutlet | 抽屜裡的印章 / 拿出來蓋在這裡 |
| ng-content / ngProjectAs | 相框留空位 / 照片上貼標籤讓相框認得 |

### 重點整理

*   元件＝樣板＋類別＋樣式＋中繼資料；新版 Angular 以 standalone 元件為預設，官方建議新程式不再用 NgModule。
*   NgModule 四屬性：declarations 宣告自有項目、imports 拿別人的、exports 給別人用、providers 註冊服務。
*   `ng-container` 分組但不產生 DOM 外殼；`ng-template` 是等著被實例化的樣板片段。
*   `ng-content` 接收父層投影的內容；被容器包住配對不到時用 `ngProjectAs`。

## 隨堂測驗

**Q1. 現代 Angular 中，元件標示 standalone: true 的意義是什麼？**

- (A) 元件自己管理 imports，不必宣告在任何 NgModule 的 declarations 裡
- (B) 元件不能再匯入其他元件或管道
- (C) 元件只能使用行內樣板，不能用 templateUrl
- (D) 元件會自動註冊成全域服務

<details><summary>看答案</summary>

**答案：(A)** standalone 元件把需要的東西列在自己的 imports，脫離 NgModule 的登記制。

</details>

**Q2. 元件的 TypeScript 類別負責什麼？**

- (A) 這塊畫面的狀態與事件處理邏輯
- (B) 定義畫面的 HTML 結構
- (C) 限制樣式只作用在這個元件
- (D) 決定路由配對到哪個頁面

<details><summary>看答案</summary>

**答案：(A)** HTML 結構是樣板的事、樣式隔離是樣式與封裝的事；類別管狀態與行為。

</details>

**Q3. ng-container 最重要的特性是什麼？**

- (A) 能把多個節點包成一組，但不會產生額外的 DOM 元素
- (B) 會自動套用元件的樣式封裝
- (C) 只能搭配 ngTemplateOutlet 使用
- (D) 它的內容預設不會顯示，要另外實例化

<details><summary>看答案</summary>

**答案：(A)** 它是邏輯容器；「內容預設不顯示、要實例化」說的是 ng-template。

</details>

**Q4. 為何 ng-template 的內容預設不會顯示？**

- (A) 它定義的是樣板片段，要由控制流程或 ngTemplateOutlet 實例化才會出現
- (B) 它必須先在 NgModule 的 declarations 宣告
- (C) 它只有在元件銷毀前的最後一次變更偵測才渲染
- (D) 它的內容會被 ng-content 的插槽攔截

<details><summary>看答案</summary>

**答案：(A)** ng-template 是先寫好、等著被放上舞台的布景，不實例化就不出現。

</details>

**Q5. ngTemplateOutlet 的用途是什麼？**

- (A) 在指定位置實例化某個 ng-template，還能用 context 帶參數
- (B) 把子元件的樣板整份複製到父元件
- (C) 宣告一個新的路由出口
- (D) 把元件的樣式穿透到子元件

<details><summary>看答案</summary>

**答案：(A)** outlet 是「放置的出口」：把參照到的樣板放進目前位置，context 可傳值。

</details>

**Q6. 內容投影（ng-content）最適合解決哪種需求？**

- (A) 子元件定共同版型，內容由父元件決定
- (B) 父元件要讀取子元件的私有屬性
- (C) 兩個兄弟元件要共用同一份服務
- (D) 清單重新排序時要重用 DOM 節點

<details><summary>看答案</summary>

**答案：(A)** ng-content 是元件預留的插槽；共用服務靠依賴注入、清單重用靠 track。

</details>

**Q7. 傳統 NgModule 的 declarations 放什麼？**

- (A) 屬於該模組的非 standalone 元件、指令與管道
- (B) 要提供給依賴注入的服務
- (C) 要公開給其他模組使用的項目
- (D) 應用程式啟動時要先執行的初始化函式

<details><summary>看答案</summary>

**答案：(A)** 服務放 providers、公開項目放 exports；declarations 是模組自有的宣告項目。

</details>

**Q8. 投影的節點被 ng-container 包住、select 配對不到時，該怎麼辦？**

- (A) 在該節點加上 ngProjectAs，指定要視為哪種選擇器
- (B) 把 ng-content 改成 ng-template
- (C) 替 ng-container 加上 CSS class 讓選擇器找得到
- (D) 改用 ngTemplateOutlet 重新投影一次

<details><summary>看答案</summary>

**答案：(A)** ngProjectAs 明確告訴 Angular 這個節點該配對哪個插槽；ng-container 不會渲染，加 class 也沒用。

</details>
