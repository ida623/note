## @for 與 track

> 🏠 **生活比喻**
>
> 想像老師在教室**換座位**：
> - 用**學號**（`track item.id`）認人：大家換位子後，老師知道「王小明還是王小明」，只要搬他的書包就好。
> - 用**座位號**（`$index`）認人：一換位子，老師就以為 3 號座位的人還是同一個，結果認錯一堆人，只好全班重新認識（整批重建 DOM）。
>
> 所以只有「座位永遠不會換」的班級（靜態清單），才適合用座位號點名。

```
@for (course of courses; track course.id;
      let i = $index, first = $first, count = $count) {
  <article [class.first-item]="first">
    {{ i + 1 }} / {{ count }}：{{ course.name }}
  </article>
} @empty {
  <p>目前沒有課程</p>
}
```

`track` 像每件行李上的固定識別牌：清單重新排序或更新時，Angular 靠它認出哪個 DOM 節點仍代表同一筆資料，只更新有變的項目，不必整批拆掉重建。沒有穩定識別值時，資料一變就重建所有 DOM，清單一大就慢。

資料有穩定 ID 就用 `item.id`；只有「不會插入、刪除、重新排序」的靜態清單，才適合用 `$index` 追蹤。`$index`、`$first`、`$count` 這些開頭的 `$` 表示是 Angular 提供的內建變數，跟你自己資料裡的變數區隔開來。

## 看懂 \*ngIf、\*ngFor 與 \*ngSwitch

> 🏠 **生活比喻**
>
> `*ngIf`、`*ngFor` 像**舊地名**（例如「台北縣」），`@if`、`@for` 是**新地名**（「新北市」）。
> 現在寄信寫新地名，但翻老文件時還是會看到舊地名，所以兩個都要認得。

既有專案仍到處是星號語法。結構型指令會新增、移除 DOM 元素：`*ngIf`、`*ngFor`、`*ngSwitchCase`、`*ngSwitchDefault` 都要加星號；容器上的 `[ngSwitch]` 本身不加。

```
<div [ngSwitch]="status">
  <p *ngSwitchCase="'ready'">可以開始</p>
  <p *ngSwitchDefault>準備中</p>
</div>
```

新程式優先用 `@if`、`@for`、`@switch`；星號寫法是維護舊專案時要認得的字彙。

## 四種常用綁定

> 🏠 **生活比喻**
>
> - **插值 `{{ }}`**＝店門口的**電子看板**：類別裡的文字直接顯示出來。
> - **屬性綁定 `[ ]`**＝**冷氣遙控器**：類別這邊設定溫度，畫面上的冷氣跟著照做。
> - **事件綁定 `( )`**＝**門鈴**：客人在畫面上按了，就通知類別「有人來了」。
> - **雙向綁定 `[( )]`**＝**共用的白板**：你寫上去我看得到，我擦掉改寫你也看得到。其實就是「遙控器＋門鈴」一起用。

| 語法 | 方向 | 用途 |
| --- | --- | --- |
| `{{ title }}` | 類別 → 畫面 | 文字插值。 |
| `[src]="imageUrl"` | 類別 → DOM 屬性 | 屬性綁定。 |
| `(click)="select(id)"` | 畫面 → 類別 | 事件綁定。 |
| `[(ngModel)]="name"` | 雙向 | 表單值同步。 |

> 方括號綁資料、圓括號接事件；雙向綁定＝屬性綁定＋事件綁定

`[(ngModel)]` 的值從類別流向畫面靠屬性綁定，使用者改了輸入框再流回類別靠事件綁定，兩者合起來就是雙向。standalone 元件要在 `imports` 加入 `FormsModule` 才能用 `ngModel`。雙向綁定方便，但欄位多、驗證複雜的表單通常更適合響應式表單（Reactive Forms，在 TypeScript 裡明確定義表單結構與驗證）。

## 用 class 表達狀態

> 🏠 **生活比喻**
>
> - `[class.名稱]`＝**單一電燈開關**：開或關一盞燈。
> - `[ngClass]`＝**整排開關面板**：一次控制好幾盞燈。
>
> 只要開一盞燈，用單一開關最直覺。

```
<button
  [class.course-type]="i === selectedIndex"
  (click)="selectedIndex = i">
  {{ course.name }}
</button>
```

只切換單一 class 時，`[class.名稱]` 配一個布林值最清楚；要一次管理多個 class 再用 `[ngClass]`。

```
<article [ngClass]="{
  selected: course.id === selectedId,
  disabled: !course.available
}">...</article>
```

*【設計觀念】*

## 單向資料流與 MVVM

> 🏠 **生活比喻**
>
> **單向資料流**像**河流**：水從上游（類別）流到下游（畫面）。下游的人想改變什麼，要打電話通知上游（事件），由上游調整水量。河水被汙染時，只要往上游一路找，就能找到源頭。
>
> **MVVM** 像**餐廳**：
> - **Model**＝廚房的食材和食譜（資料與規則）
> - **View**＝客人看到的餐桌（畫面）
> - **ViewModel**＝**服務生**：把廚房的菜端到桌上，也把客人的點餐傳回廚房。Angular 的元件類別就像這位服務生。

Angular 的常態是：元件類別的狀態推動畫面更新（類別 → 畫面），畫面上的操作透過事件通知類別改狀態（畫面 → 類別）。只綁資料不綁事件時，在畫面上怎麼點，類別裡的值都不會變——這就是單向資料流；方向清楚，出問題時才追得到源頭。

MVVM 是一種理解方式（Model–View–ViewModel，資料層、畫面層、居中銜接層）：

*   **Model**：應用程式的資料與規則。
*   **View**：使用者看到的樣板。
*   **ViewModel**：把狀態與操作提供給 View；在 Angular 裡，元件類別扮演相近的角色。

MVVM 是幫助理解的地圖，不必把 Angular 每個機制硬套進去。

### 🗺️ 比喻對照表

| 技術名詞 | 生活比喻 |
| --- | --- |
| track item.id / $index | 用學號認人 / 用座位號認人 |
| *ngIf → @if | 舊地名 → 新地名 |
| {{ }} 插值 | 電子看板 |
| [ ] 屬性綁定 | 冷氣遙控器 |
| ( ) 事件綁定 | 門鈴 |
| [( )] 雙向綁定 | 共用白板 |
| [class.x] / [ngClass] | 單一電燈開關 / 整排開關面板 |
| 單向資料流 | 河流由上游往下游 |
| MVVM | 廚房 / 餐桌 / 服務生 |

### 重點整理

*   `@for` 的 `track` 要用穩定識別值，Angular 才能重用 DOM；靜態清單才用 `$index`。
*   方括號綁資料（類別 → 畫面）、圓括號接事件（畫面 → 類別）。
*   `[(ngModel)]`＝屬性綁定＋事件綁定，要匯入 `FormsModule`。
*   單一 class 用 `[class.名稱]`，多個才用 `[ngClass]`。
*   新程式用 `@if`／`@for`／`@switch`；星號結構指令是讀舊專案的必備字彙。

**Q1. @for 中 track course.id 的主要用途是什麼？**

- (A) 讓 Angular 認出同一筆資料，只更新有變的 DOM 節點
- (B) 把 id 顯示在畫面上方便除錯
- (C) 限制清單最多渲染的筆數
- (D) 讓清單自動依 id 排序

<details><summary>看答案</summary>

**答案：(A)** track 提供穩定識別值，清單變動時 Angular 才能重用 DOM 而不是整批重建。

</details>

**Q2. 哪種情況適合用 $index 當 track？**

- (A) 清單固定、不會插入刪除或重新排序
- (B) 項目會頻繁重新排序
- (C) 每筆資料都有穩定的唯一 ID
- (D) 清單常從中間刪除項目

<details><summary>看答案</summary>

**答案：(A)** 清單會變動時用索引，位置一移就把不同資料誤認成同一項；有穩定 ID 就該用 ID。

</details>

**Q3. [src]="imageUrl" 屬於哪種綁定？**

- (A) 屬性綁定：類別的值流向 DOM 屬性
- (B) 事件綁定：畫面的操作流回類別
- (C) 雙向綁定：值來回同步
- (D) 插值：把字串嵌進文字內容

<details><summary>看答案</summary>

**答案：(A)** 方括號是屬性綁定；插值是 {{ }}，事件是圓括號。

</details>

**Q4. (click)="save()" 這段語法表示什麼？**

- (A) 收到 click 事件時執行類別的 save 方法
- (B) 把 save 的回傳值綁定到按鈕文字
- (C) 宣告一個叫 click 的輸出事件
- (D) 建立 save 與畫面之間的雙向同步

<details><summary>看答案</summary>

**答案：(A)** 圓括號接事件：畫面發生 click，通知類別執行 save。

</details>

**Q5. standalone 元件要使用 [(ngModel)]，imports 需要加什麼？**

**Q6. 只需依布林值切換單一 CSS class，最直接的寫法是？**
