*【元件的一生】*

## 生命週期 hook：在對的時機做對的事

> 🏠 **生活比喻**
>
> 把元件想成一位**新進員工的職涯**：
> - `constructor`＝**錄取報到**，領識別證和工具（依賴注入在這裡發生），但還沒開始做事。
> - `ngOnChanges`＝主管**交辦的內容改了**，員工要跟著調整。
> - `ngOnInit`＝**第一天正式上工**，把桌面整理好、做開工準備（只做一次）。
> - `ngAfterViewInit`＝**團隊成員都到齊了**，終於可以找同事開會。
> - `ngOnDestroy`＝**離職前交接**：退掉訂閱的報紙、關掉鬧鐘、歸還門禁卡。
>
> 「變更偵測」就像主管定時巡視，看看大家的工作有沒有更新。

Angular 建立元件後會反覆進行變更偵測（檢查綁定的資料有沒有變、需不需要更新畫面），直到元件被移除、銷毀。生命週期 hook（掛勾函式，Angular 在特定時機自動呼叫的方法）讓你把程式掛在這些時機上。常用的四個：

| Hook | 適合用途 |
| --- | --- |
| `ngOnChanges` | 回應輸入值的變化；元件有綁定的輸入值時才會被呼叫。 |
| `ngOnInit` | 輸入初值都就緒後，執行一次初始化。 |
| `ngAfterViewInit` | 檢視與子元件都建立完成後，使用檢視查詢的結果。 |
| `ngOnDestroy` | 元件退場前，取消訂閱、清計時器、釋放資源。 |

完整的初始化順序是 constructor → `ngOnChanges` → `ngOnInit` → `ngDoCheck` → `ngAfterContentInit` → `ngAfterContentChecked` → `ngAfterViewInit` → `ngAfterViewChecked`，銷毀時才是 `ngOnDestroy`[出處](https://angular.dev/guide/components/lifecycle)；而且 `ngOnChanges` 只有在元件有綁定的輸入值、且至少一個值變了才會執行[出處](https://angular.dev/api/core/OnChanges)。

`constructor` 是 TypeScript 類別本身的建構函式，不算 Angular 的生命週期 hook；依賴注入在這裡發生，但初始化邏輯建議放 `ngOnInit`。

*【父傳子】*

## Input 是子元件的資料入口

> 🏠 **生活比喻**
>
> 子元件像**廚師**，父元件像**外場**遞過去的**點餐單**。
> 廚師不會自己決定做什麼菜，而是看單子做；同一位廚師可以替不同客人做不同的菜（元件重用）。
> `[course]="selectedCourse"` 就是「把這張點餐單（父的 selectedCourse）交給廚師的 course 欄位」。

子元件能被多個父元件重用（例如課程卡片），資料就不能寫死在子元件裡，而是由父元件傳進來。

```
// 子元件
@Input({ required: true }) course!: Course;
```

```
<!-- 父元件樣板 -->
<app-course-card [course]="selectedCourse" />
```

方括號左側的 `course` 是子元件公開的輸入名稱，右側的 `selectedCourse` 是父元件的運算式——「子元件的變數＝父元件的變數」。新版 Angular 另有以 signal 為基礎的 `input()` 寫法；讀舊程式時看到的多半是 `@Input`。

*【子傳父】*

## Output 把事件送回父元件

> 🏠 **生活比喻**
>
> 廚師做好菜，就**按一下出餐鈴**（`emit`），外場聽到鈴聲（`(selected)`）來端菜；`$event` 就是那盤菜。
> 鈴聲的名字要描述「發生了什麼」（「餐好了」selected），而不是命令別人（「快來端」）。

```
// 子元件
@Output() selected = new EventEmitter<Course>();

choose(): void {
  this.selected.emit(this.course);
}
```

```
<app-course-card
  [course]="course"
  (selected)="openCourse($event)" />
```

父元件用圓括號接子元件的輸出事件，`$event` 就是 `emit` 送出來的資料。事件名稱描述「發生了什麼」（selected、deleted），不要取成命令句。

新版 Angular 也提供 `output()` 寫法；`EventEmitter` 仍是最常見、必須看懂的形式。

*【呼叫子元件】*

## 樣板參照變數與 ViewChild

> 🏠 **生活比喻**
>
> - **樣板參照變數 `#counter`**＝在遙控器上**貼名字標籤**，要用時直接拿起來按。
> - **`@ViewChild`**＝主管**查員工名冊**找到某人，再請他做事。
> - `static: false`（預設）就像新員工要等**報到流程全跑完**（`ngAfterViewInit`）才會出現在名冊上；你在 `ngOnInit` 就去查，名冊上還找不到人（undefined）。
>
> 能用點餐單（Input）和出餐鈴（Output）溝通，就別直接跑進廚房指揮廚師，彼此比較不會綁死。

只在樣板裡呼叫子元件的公開方法時，樣板參照變數（`#` 開頭，替樣板中的元素取名）最簡單：

```
<app-counter #counter />
<button (click)="counter.increment()">加一</button>
```

父元件的 TypeScript 要拿到子元件實例時，用檢視查詢 `@ViewChild`：

```
@ViewChild(CounterComponent)
counter?: CounterComponent;

ngAfterViewInit(): void {
  this.counter?.increment();
}
```

查詢結果何時可用取決於 `static` 設定：預設（`static: false`）在 `ngAfterViewInit` 之前解析，所以 `ngOnInit` 拿到的是 undefined；設 `static: true` 則在 `ngOnInit` 之前就解析好，但結果不會隨檢視變動更新[出處](https://angular.dev/api/core/ViewChild)。

能用 Input／Output 描述父子關係時，通常比直接呼叫子元件方法更鬆耦合。

*【顯示轉換】*

## Pipe 專心把值轉成適合顯示的樣子

> 🏠 **生活比喻**
>
> Pipe 像手機相機的**濾鏡**：原始照片不變，只是顯示時換個樣子（日期換格式、數字加上 $）。
> 濾鏡只負責「好看」，不能拿濾鏡去寄信或改照片原檔（不要有副作用、不要發 HTTP 請求）。

```
<p>{{ today | date:'yyyy-MM-dd' }}</p>
<p>{{ price | currency:'TWD':'symbol':'1.0-0' }}</p>
```

管道（Pipe）像水管末端的濾嘴：值流過去、以另一種樣子呈現，來源資料不動。standalone 元件可直接匯入需要的管道（`DatePipe`、`CurrencyPipe`…），或匯入包含常用管道的 `CommonModule`。自訂管道適合可重複、無副作用的顯示轉換，不適合發 HTTP 請求或改資料。

```
@Pipe({ name: 'initials', standalone: true })
export class InitialsPipe implements PipeTransform {
  transform(name: string): string {
    return name.split(/\s+/).map(part => part[0]).join('');
  }
}
```

*【共用能力】*

## Service 與依賴注入

> 🏠 **生活比喻**
>
> Service 像**飯店的客房服務**，依賴注入就是**打電話叫客房服務**：
> - 你需要毛巾，打電話（`inject(CourseService)`），飯店就送來，不用自己跑去買（自己 `new`）。
> - `providedIn: 'root'`＝全飯店共用同一個客房服務部。
> - **注入情境（injection context）**＝只有在**入住登記時**能填需求單；半夜臨時跑去櫃台補填，櫃台不受理（會報錯）。

跨多個元件的共用邏輯、資料存取或狀態，抽成服務（Service）。服務經由依賴注入（Dependency Injection，需要什麼由框架送進來，不用自己 new）提供給元件，比元件之間層層呼叫更容易測試與替換。

```
@Injectable({ providedIn: 'root' })
export class CourseService {
  getCourses(): Course[] {
    return [];
  }
}
```

元件要拿到服務，用 `inject()` 函式在類別欄位宣告時直接取：寫 `inject(CourseService)`，Angular 就把對應的實例送進來，之後用 `this.courseService` 呼叫它的方法即可。之後的程式裡出現的 `this.router`、`this.heroService`、`this.http` 都是這樣拿到的[出處](https://angular.dev/guide/di)。

```
import { Component, inject } from '@angular/core';

@Component({ selector: 'app-course-list', /* ... */ })
export class CourseListComponent {
  private courseService = inject(CourseService);
  courses: Course[] = [];

  ngOnInit(): void {
    this.courses = this.courseService.getCourses();
  }
}
```

`inject()` 要在元件、指令或服務「建構期間」呼叫——寫在欄位初始值或建構函式本體裡都可以，官方把這種可以呼叫的地方稱為注入情境（injection context）；在其他時機（例如按鈕事件的處理函式裡）呼叫會報錯。

## 訊號（signals）：官方現行主推的寫法

> 🏠 **生活比喻**
>
> 訊號很像 **Excel 試算表**：
> - `signal()`＝一個**儲存格**，值改了會自動通知用到它的地方。
> - `computed()`＝**公式格**（像 `=A1*2`），只有 A1 變了才重算。
> - `effect()`＝設定「A1 一變就**寄 email 通知**」這種附帶動作。
> - `input()`＝**鎖定的儲存格**，子元件只能看、不能改。
>
> 舊的裝飾器寫法則像主管每隔一陣子**把整張表從頭掃一遍**，看看哪裡變了。

上面講的 `@Input`／`@Output`／`EventEmitter` 是裝飾器寫法，既有專案裡大多長這樣。現行的主要寫法是**訊號（signal，一個「會通知誰在用我」的值）**：元件輸入以 `input()` 為主，`@Input` 裝飾器仍完整支援[出處](https://angular.dev/guide/components/inputs)。新專案會直接遇到訊號，兩種寫法對照如下。

| 要做的事 | 裝飾器寫法 | 訊號寫法（官方現行） |
| --- | --- | --- |
| 接收父元件的值 | `@Input() value = 0;` | `value = input(0);`（讀值要加括號：`this.value()`） |
| 必填的輸入 | `@Input({ required: true }) id!: string;` | `id = input.required<string>();` |
| 往父元件送事件 | `@Output() saved = new EventEmitter<void>();` | `saved = output<void>();` |
| 自己管一個會變的值 | 普通屬性，靠變更偵測掃描 | `count = signal(0);`，改值用 `this.count.set(1)` 或 `update()` |
| 由其他值算出來的值 | getter 或在樣板裡算 | `double = computed(() => this.count() * 2);`——來源變了才重算 |

`signal()` 建立一個可讀可寫、會通知使用者的值；`computed()` 從其他訊號算出唯讀的值，來源沒變就不重算；`effect()` 在訊號變動時做副作用（例如寫入瀏覽器儲存）。`input()` 回傳的是唯讀訊號，所以只能讀、不能在子元件裡改。

> 舊專案看得懂裝飾器，新專案直接寫訊號

### 🗺️ 比喻對照表

| 技術名詞 | 生活比喻 |
| --- | --- |
| constructor → ngOnInit → ngOnDestroy | 錄取報到 → 正式上工 → 離職交接 |
| @Input | 交給廚師的點餐單 |
| @Output / emit / $event | 出餐鈴 / 按鈴 / 那盤菜 |
| #ref / @ViewChild | 遙控器貼名字 / 查員工名冊 |
| Pipe | 相機濾鏡，原圖不變 |
| Service + inject() | 打電話叫客房服務 |
| signal / computed / effect | Excel 儲存格 / 公式格 / 變了就寄通知 |

### 重點整理

*   官方建議新專案用訊號寫法：`input()`／`output()`／`signal()`／`computed()`；`@Input` 等裝飾器仍完整支援，用於維護既有專案。
*   元件拿服務用 `inject(XxxService)` 寫在欄位初始值；`inject()` 只能在建構期間呼叫。
*   初始化寫在 `ngOnInit`、清理寫在 `ngOnDestroy`；`ngOnChanges` 只在有綁定輸入值時執行。
*   父傳子用 Input（`[子元件變數]="父元件變數"`），子傳父用 Output＋`$event`。
*   `@ViewChild` 預設在 `ngAfterViewInit` 前解析；`static: true` 才能在 `ngOnInit` 前拿到。
*   Pipe 只做無副作用的顯示轉換；跨元件的共用邏輯交給 Service 與依賴注入。

**Q1. 清除計時器與取消訂閱，最適合寫在哪個 hook？**

- (A) ngOnDestroy
- (B) ngOnInit
- (C) ngAfterViewInit
- (D) ngOnChanges

<details><summary>看答案</summary>

**答案：(A)** 元件退場前釋放資源；其他三個都在元件還活著的階段。

</details>

**Q2. ngOnChanges 在什麼情況下才會被呼叫？**

- (A) 元件有綁定的輸入值、且輸入值發生變化時
- (B) 每一次變更偵測都會呼叫
- (C) 只有元件銷毀前的最後一刻
- (D) 只有搭配 static: true 的檢視查詢時

<details><summary>看答案</summary>

**答案：(A)** 沒有綁定輸入值的元件不會觸發 ngOnChanges；每次變更偵測都跑的是 ngDoCheck。

</details>

**Q3. 父元件要把 course 資料傳給子元件，子元件該用什麼接？**

- (A) @Input 屬性
- (B) @Output 事件
- (C) @ViewChild 查詢
- (D) providedIn: 'root' 的服務

<details><summary>看答案</summary>

**答案：(A)** Input 是子元件的資料入口；Output 是往外送事件、ViewChild 是父元件往下抓。

</details>

**Q4. 子元件要通知父元件「使用者選了一門課」，標準做法是什麼？**

- (A) @Output 搭配 EventEmitter 發出事件
- (B) 直接 import 父元件並呼叫它的方法
- (C) 把選取結果寫進全域變數讓父元件輪詢
- (D) 用 @Input 把父元件的函式覆寫掉

**答案：(A)** 子傳父走事件：emit 出去，父元件用 (selected)="..." 接。

</details>

**Q5. 父元件樣板裡 (selected)="openCourse($event)" 的 $event 是什麼？**

**答案：(A)** 對自訂輸出事件而言，$event 就是 EventEmitter 送出的值。

</details>

**Q6. @ViewChild 查詢預設（static: false）何時解析完成？**

- (A) ngAfterViewInit 之前
- (B) constructor 執行時
- (C) ngOnInit 之前
- (D) 元件銷毀時

<details><summary>看答案</summary>

**答案：(A)** 預設要等檢視建立完；要在 ngOnInit 前拿到得設 static: true，且結果不隨檢視變動更新。

</details>

**Q7. 哪種工作適合寫成自訂 Pipe？**

- (A) 把姓名轉成縮寫這類無副作用的顯示轉換
- (B) 在值變化時發 HTTP 請求同步後端
- (C) 直接修改來源陣列的排序
- (D) 攔截路由導覽並檢查權限

<details><summary>看答案</summary>

**答案：(A)** Pipe 該是純轉換：不打 API、不改來源資料；路由攔截是守衛的事。

</details>

**Q8. 多個元件要共用同一套資料存取邏輯，該放哪裡？**

- (A) 可注入的 Service
- (B) 每個元件各複製一份方法
- (C) 塞進共同父元件再層層往下傳
- (D) 寫在樣板參照變數上

<details><summary>看答案</summary>

**答案：(A)** 服務配合依賴注入集中邏輯，最容易測試與替換；層層傳遞會把元件綁死。

</details>
