*【資產與圖示】*

## 靜態資產放哪裡

> 🏠 **生活比喻**
>
> 靜態資產就像家裡的**儲藏室**：圖片、字型都收在這。新房子（Angular 18+）的儲藏室在 `public/`，老房子在 `src/assets`。
> 改了 `angular.json`，像改了家具配置圖，要**重新整理房子**（重啟開發伺服器）才看得到效果。
> 圖示只註冊用得到的，就像**出門旅行只帶需要的東西**，行李才不會越塞越重。

圖片、字型等靜態資產放在專案設定指定的資產目錄。Angular 18 起，新專案的預設資產目錄是與 `src/` 同層的 `public/`（`angular.json` 的 assets 設定指向它）；`src/assets` 是舊版預設，既有專案仍可沿用或在 `angular.json` 自行設定[目錄說明](https://angular.dev/reference/configs/file-structure)[v18 改版紀錄](https://github.com/angular/angular-cli/releases/tag/18.0.0)。改了 `angular.json` 的建置設定後，記得重新啟動開發伺服器才會生效。

> 📝 查證更正：原筆記寫「我們經常需要添加靜態資源到專案內，通常會將其存放在 ./src/assets 中」，查證後更正：Angular 18 起新專案預設改用 public/ 目錄

圖示套件也一樣：只註冊真正用到的圖示，像出門只帶會用到的工具，避免把整套圖示全部打包進產出檔、讓專案越長越肥。

*【樣式架構】*

## 全域樣式與元件樣式各司其職

> 🏠 **生活比喻**
>
> - **全域樣式**＝公司的**品牌識別手冊**：標準色、字體、間距，全公司一起遵守。
> - **元件樣式**＝各部門自己的佈置，只管自己的辦公室。
> - **CSS 變數**＝替顏料桶取名字（「品牌藍」）：換掉這桶顏料，全公司用到它的地方一起變色，深色模式就是這樣切的。
> - 第三方套件的基礎樣式像 **IKEA 家具附的五金零件**：少了它，家具功能都在，但組起來歪七扭八。

全域樣式（`styles.css` 或 `styles.less`）放色彩變數、文字規格、間距與重設規則；元件樣式只描述該元件自己。預處理器（SCSS 或 Less，先寫變數與巢狀再編譯成 CSS 的工具）在建立專案時選定最省事，之後也能改檔名並同步修改 `angular.json` 的 styles 設定。

```
:root {
  --color-bg: #ffffff;
  --color-text: #202124;
}

:root[data-theme='dark'] {
  --color-bg: #171717;
  --color-text: #f3f3f3;
}

body {
  background: var(--color-bg);
  color: var(--color-text);
}
```

用第三方 UI 套件（如 Ant Design）時，還要照套件文件載入它的基礎樣式；把基礎樣式拿掉，元件功能還在、外觀卻會整個失靈。

*【樣式封裝】*

## 為何父元件的 CSS 套不到子元件

> 🏠 **生活比喻**
>
> 像**公寓**：每間房間的油漆都貼著自己的房號，你在客廳刷紅漆，不會刷到隔壁房間（樣式封裝）。
> - `:host`＝這間房間的**門框本身**。
> - `::ng-deep`＝**萬能鑰匙**，可以闖進所有房間亂刷油漆，房東（Angular 官方）強烈不建議。
>
> 想改第三方元件的外觀，先問房東有沒有提供「可調整的選項」（主題 API、CSS 變數），真的沒有才自己動手。

Angular 預設做檢視封裝（View Encapsulation）：編譯時替每個元件的元素加上專屬的屬性選擇器，像替每間房間的油漆貼上房號，元件樣式就不會外洩污染別的區域。這也是為什麼在父元件寫 `p { color: red }`，子元件的 `<p>` 不會變紅。

`:host` 用來選取元件自己的宿主元素（元件標籤本身，例如 `<app-card>`）：

```
:host {
  display: block;
}

:host .title {
  font-weight: 700;
}
```

`::ng-deep` 會拆掉封裝、讓選擇器穿透到子元件，今天仍然能用，但 Angular 官方強烈不建議新程式使用，保留它只是為了回溯相容[出處](https://angular.dev/guide/components/styling)。

要客製第三方元件的外觀，優先順序是：套件提供的主題 API、CSS 變數、可設定的 class，再來才是範圍收窄的全域樣式。

*【偏好保存】*

## localStorage、sessionStorage、Cookie 與 Session

> 🏠 **生活比喻**
>
> HTTP **無狀態**＝店員是**健忘的**，每次你走進店裡他都不記得你是誰（但這跟電話有沒有掛斷是兩回事）。所以要靠其他方式「記住」：
> - **localStorage**＝**貼在自家冰箱上的便條**：一直都在，家裡每個人（同源的分頁）都看得到。
> - **sessionStorage**＝**飯店房間的便條紙**：退房（關閉分頁）就被清掉。
> - **Cookie**＝**會員卡**：每次去店裡結帳都自動出示給店家看。
> - **伺服器 Session**＝**寄物櫃**：東西放在店裡，你手上只拿一張號碼牌。
>
> 把登入權杖（JWT）放 localStorage，就像**把家門鑰匙貼在冰箱上**：小偷（XSS 攻擊）一進屋就能拿走。

HTTP 本身無狀態，指的是伺服器不記得上一個請求是誰發的，而不是每次都要重新建立連線[無狀態的定義](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)[連線重用](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Connection_management_in_HTTP_1.x)。要讓「使用者選的主題」或「登入狀態」留下來，得靠瀏覽器端或伺服器端的保存機制：

> 📝 查證更正：原筆記寫「HTTP 為無狀態協議，每次請求、獲取數據，前端頁面與服務端都需要重新連接」，查證後更正：無狀態指的是伺服器不保留前一個請求的狀態，與底層連線是否重用是兩回事——HTTP/1.1 起預設 keep-alive，同一條 TCP 連線可以連續送很多個請求

| 機制 | 生命週期與範圍 | 適合用途 |
| --- | --- | --- |
| `localStorage` | 同源下持續保存，同源的各分頁都讀得到 | 主題、語言等非敏感偏好 |
| `sessionStorage` | 只限單一分頁的工作階段，關閉即消失 | 單次流程的暫存狀態 |
| Cookie | 可設過期時間，符合規則時隨每次 HTTP 請求送出 | 由伺服器讀取的識別資訊（單顆約 4KB） |
| 伺服器 Session | 資料放伺服器，瀏覽器通常只拿一個識別碼 | 登入狀態與敏感的工作階段資料 |

Web Storage（localStorage 與 sessionStorage 的統稱）只能存字串，物件要先用 JSON 轉換。敏感憑證（例如登入用的 JWT，JSON Web Token，一串夾帶登入身分、附簽章的權杖字串）不要只因為方便就放 localStorage[出處](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage)。

> 📝 查證更正：原筆記把「用戶登入狀態（配合 JWT token）」列為 localStorage 的適用場景，查證後更正：localStorage 的內容任何同源的 JavaScript 都讀得到，跨站腳本攻擊（XSS）一旦得手就能整包帶走；OWASP 建議權杖不要放在 Web Storage

*【主題初始化】*

## 在第一個畫面出現前套回偏好

> 🏠 **生活比喻**
>
> 像**開店前先把燈光調好**：如果開門後才調，客人會先看到亮白燈再突然變暗（畫面閃一下）。
> `provideAppInitializer` 就是**開門前的檢查清單**，清單上的事做完（Promise / Observable 完成），才拉開鐵門讓客人進來（建立根元件）。

主題存進 localStorage 之後還差一步：重新整理頁面時，要在畫面出現前把它讀回來套用，不然會先閃一下預設主題。Angular 的應用程式初始化機制就是做這件事。要注意寫法換過一輪：`APP_INITIALIZER` 這個舊寫法自 Angular 19 起標記為棄用，官方建議改用 `provideAppInitializer`（[出處](https://angular.dev/api/core/APP_INITIALIZER)）：

```
import { provideAppInitializer, inject } from '@angular/core';

export const appConfig = {
  providers: [
    provideAppInitializer(() => {
      const theme = inject(ThemeService);
      theme.apply(localStorage.getItem('theme') ?? 'light');
    })
  ]
};
```

啟動流程概念上是：執行進入點 `main.ts` → 讀取應用程式設定 `app.config.ts` → 執行所有初始化函式 → 建立根元件。初始化函式回傳 Promise（代表一件還沒完成的非同步工作）或 Observable（RxJS 的資料流物件，值會陸續送來、要訂閱才拿得到）時，Angular 會等它完成才往下走。

*【瀏覽器安全邊界】*

## 同源政策與 CORS

> 🏠 **生活比喻**
>
> **同源**＝**同一個地址、同一個入口、同一間房號**（協定＝走哪個大門、主機＝地址、埠號＝房號），三樣都一樣才算自家人。
> **CORS** 像**住戶在警衛室留訪客名單**：是被拜訪的住戶（伺服器）說「這個人可以上來」，不是訪客（前端）自己說了算。

兩個網址要通訊協定、主機、埠號三者都相同才算同源（路徑不同沒關係）。localStorage 與 sessionStorage 都受同源邊界限制：別的網站讀不到你網站存的東西。CORS（跨來源資源共享）不是把同源政策關掉，而是伺服器透過回應標頭，明確允許特定來源讀取跨來源的回應。

> 同源＝通訊協定相同＋主機相同＋埠號相同

### 🗺️ 比喻對照表

| 技術名詞 | 生活比喻 |
| --- | --- |
| public/ 資產目錄 | 家裡的儲藏室 |
| 全域樣式 / CSS 變數 | 公司品牌手冊 / 有名字的顏料桶 |
| View Encapsulation | 每間房的油漆貼房號 |
| ::ng-deep | 萬能鑰匙，房東不建議 |
| localStorage / sessionStorage | 冰箱便條 / 飯店便條紙 |
| Cookie / Session | 會員卡 / 寄物櫃號碼牌 |
| provideAppInitializer | 開門前的檢查清單 |
| 同源 / CORS | 同地址同房號 / 住戶留的訪客名單 |

### 重點整理

*   Angular 18 起新專案的靜態資產預設放 `public/`；改建置設定要重啟開發伺服器。
*   全域樣式管變數與規格，元件樣式管自己；檢視封裝靠編譯期的屬性選擇器隔離。
*   客製第三方元件優先用正式主題 API；`::ng-deep` 官方強烈不建議新用。
*   主題偏好放 localStorage，啟動時用 `provideAppInitializer` 套回（`APP_INITIALIZER` 自 v19 起棄用）。
*   同源＝協定＋主機＋埠號都相同；CORS 是伺服器開白名單，不是前端片面放行。
