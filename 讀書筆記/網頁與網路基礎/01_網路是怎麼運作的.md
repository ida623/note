## 網際網路不只是一堆電纜

網際網路（Internet）是由許多彼此連接的網路組成的「網路之網」——除了纜線，還有路由器、交換器、伺服器，以及大家共同遵守的通訊協定[出處](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/How_does_the_Internet_work)。家用網路、公司網路、電信商骨幹與資料中心，會透過光纖、海底電纜、銅線、行動網路、微波或衛星等媒介互相連接。

> 📝 查證更正：原筆記寫「網路...其實就是線！」「這就是網路真正的樣子！一堆電纜！」，查證後更正：纜線只是傳輸媒介，網際網路是整套互連的基礎設施，還包含路由器、交換器、伺服器與通訊協定

可以把網際網路想成全球道路系統：傳輸媒介是道路，路由器像交流道，IP 位址像門牌，而通訊協定則是共同遵守的交通規則。

全球資訊網（World Wide Web，WWW）只是運行在網際網路上的其中一種服務。它主要使用 HTTP 或 HTTPS 傳送網頁資源；電子郵件、網路電話與線上遊戲也會使用網際網路，卻不等於 WWW。

## 用戶端、瀏覽器與伺服器

瀏覽器是用戶端（Client）：它替使用者提出請求、接收資料，再把內容呈現出來。伺服器（Server）則是提供資源或功能的電腦或程式，例如回傳 HTML、圖片、影片或 API 資料。

伺服器可以是實體主機、虛擬機、容器，或雲端服務上執行的伺服器軟體；除了存放檔案，也會執行運算、驗證與應用程式邏輯[出處](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_web_server)。

> 📝 查證更正：原筆記寫「伺服器是直接連接到電纜上的超級電腦，沒有螢幕、滑鼠和鍵盤，只是為了儲存資料」，查證後更正：web server 可指硬體也可指軟體，動態網站還會由應用程式執行邏輯、即時產生內容

HTML 描述頁面的內容與結構，CSS 負責外觀，JavaScript 負責互動。瀏覽器取得這些資源後，才會解析並呈現網頁。

## ISP 與路由器扮演什麼角色？

網際網路服務供應商（Internet Service Provider，ISP）提供使用者連上網際網路的服務，連線方式可能是光纖、纜線、DSL 或行動網路等技術[出處](https://developer.mozilla.org/en-US/docs/Glossary/ISP)。

> 📝 查證更正：原筆記把 ISP 展開成「Internet Server Provider」，查證後更正：S 是 Service（服務），不是 Server

資料離開裝置後，通常會經過家用路由器、ISP 網路及多個中繼路由器。每台路由器會查看目的 IP，依路由表選擇下一站。它很像轉運站，但不保證每個封包都走完全相同的路。

## IP 位址負責定位設備

IP 位址是網際網路層用來識別來源與目的地的位址。IPv4 是 32 位元，例如 `192.0.2.44`；IPv6 是 128 位元，例如 `2001:db8::44`，可提供大得多的位址空間。

IP 網段的分配是公開登記的，例如台灣大學登記了 140.112 開頭的網段。但 IP 不一定永久對應某一台實體主機：它可能由 ISP 動態分配，也可能指向負載平衡器、內容傳遞網路（CDN）或一組伺服器。

「140.112 開頭」這種說法寫成正式格式就是 `140.112.0.0/16`：斜線後面的數字代表前面幾個位元是固定的網段編號，剩下的才是可以分給各台機器的號碼。這套寫法叫 CIDR（雲端課裡也叫「CIDR 區塊」或「位址範圍」，指的是同一件事），路由器查「這個封包該往哪走」靠的就是它。想知道斜線數字怎麼換算成可用位址數、多台路由規則重疊時誰優先，見雲端 AWS 與 GCP 模組的〈GCP 網路位址與子網路〉。

## 網域名稱、URL 與 DNS 不一樣

網域名稱（Domain Name）是階層式名稱，例如 `example.com`；URL（統一資源定位符）則描述某項資源的完整位置。

> https://www.example.com:443/products?id=7

| 部分 | 範例 | 作用 |
| --- | --- | --- |
| 通訊協定 | https | 指定如何通訊 |
| 主機名稱 | www.example.com | 指出要連線的主機名稱 |
| 連接埠 | 443 | 指出主機上的服務入口 |
| 路徑 | /products | 指出資源位置 |
| 查詢字串 | id=7 | 附帶請求參數 |

`www` 只是 `example.com` 下的一個標籤（label），常被用作子網域或主機名稱，並非「系統」，也不是所有網站都必須使用[出處](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_domain_name)[出處](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_URL)。URL 與網域是不同層次的概念：同一個網域下可以有無數個 URL，URL 指向的也不只網頁，還可以是圖片、樣式檔、API 或動態內容[出處](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_URL)。

> 📝 查證更正：原筆記寫「https: 協議；www: 系統」，查證後更正：www 只是網域下的一個標籤（label），常當子網域或主機名稱用，不是「系統」，也不是必要組成。MDN「What is a domain name」：「A domain name can have many labels (or components). It is not mandatory nor necessary to have 3 labels to form a domain name.」；MDN「What is a URL」：「The domain indicates which Web server is being requested.」

> 📝 查證更正：原筆記寫「網址（URL）意思跟網域差不多」「一個網址只會對應一個網頁」，查證後更正：URL 是某項資源的完整位置，與網域是不同層次的概念，指向的也不只網頁

另一個常見的誤稱是把 com.tw 叫成「頂級網域」；嚴格說 .tw 才是頂級網域（TLD），com.tw 是 .tw 底下再分類的次級網域組合。

## DNS 如何把名稱解析成位址？

網域名稱系統（Domain Name System，DNS）負責查詢名稱相關紀錄。最常見的結果是 IPv4 的 A 紀錄或 IPv6 的 AAAA 紀錄，但 DNS 也能保存郵件、別名與名稱伺服器等資料。

裝置通常先查看瀏覽器或作業系統快取，再詢問遞迴解析器（Recursive Resolver）。若沒有快取，解析器會沿著 DNS 階層尋找：

1.  根名稱伺服器指出相關頂級網域伺服器。
2.  頂級網域（TLD）伺服器指出該網域的權威名稱伺服器。
3.  權威名稱伺服器回答正式 DNS 紀錄。
4.  遞迴解析器將結果傳回裝置，並依 TTL 暫存。

根與 TLD 伺服器回覆的是「下一站在哪」的指引（referral），由遞迴解析器自己分別去問下一站；查詢不是一站一站「往上轉發」[出處](https://aws.amazon.com/tw/route53/what-is-dns/)。快取可減少延遲與重複查詢。

> 📝 查證更正：原筆記寫「它將請求轉發至更上一層的 DNS 伺服器，這一過程會一直持續，直到查詢到根DNS伺服器或找到有效的IP位址」，查證後更正：遞迴解析器是分別去問根、TLD、權威伺服器；前兩者回覆的是「下一站在哪」的指引，查詢不是逐層往上轉發

## 封包、TCP/IP 與四層分工

網路資料會被封裝成適合傳輸的單位。不同層對資料單位有更精確的名稱；入門時可以先統稱為封包，再理解每一層加入的標頭。

| TCP/IP 層 | 負責事項 | 常見例子 |
| --- | --- | --- |
| 應用層 | 定義應用程式如何交換內容 | HTTP、DNS、SMTP |
| 傳輸層 | 端點通訊、連接埠與可靠性 | TCP、UDP |
| 網際網路層 | 跨網路定址與路由 | IP |
| 網路存取層 | 在本地媒介上傳送資料 | Ethernet、Wi-Fi |

TCP 像有簽收與補寄機制的配送：建立連線後，透過序號、確認與重傳等機制提供有序、可靠的位元組串流。TCP 把資料切成一段段的 segment（區段）傳送，每段帶有序號與檢查碼；錯誤偵測與重傳是 TCP 在傳輸層做的事，不是網路存取層[出處](https://www.rfc-editor.org/rfc/rfc9293.html)。UDP 像快速投遞：開銷較少，但本身不保證抵達、順序或不重複；應用程式可依需求自行補上機制。

> 📝 查證更正：原筆記寫「TCP 將資料拆分成封包」，又把接收端的錯誤檢查放在網路存取層，查證後更正：TCP 的資料單位叫 segment，檢查碼與重傳是 TCP 自己（傳輸層）的職責

> 💡 可靠就一定比較好嗎？不一定。檔案下載重視完整性，常適合 TCP；即時語音更怕等待，可能選 UDP 或以 UDP 為基礎、另行提供可靠性的現代協定。

### 重點整理

*   Internet 是底層的網際網路；WWW 是其上的 Web 資訊系統。
*   DNS 把好記的名稱解析成連線所需的紀錄，URL 則描述資源位置。
*   路由器依目的 IP 轉送封包；TCP 與 UDP 提供不同的傳輸取捨。
